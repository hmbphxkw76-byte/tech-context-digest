AnthropicClaude Fable 5.2 / Mythos 5.2（2026-11-09）。同一底层模型拆为两版：Fable 5.2 带强网安与生物防护、面向所有用户；Mythos 5.2 放宽网络安全与生命科学限制，仅向通过 Cyber / Life Sciences 验证计划的机构开放。输出速度较 Fable 5.1 最高 +30%；标准价格 $8/百万输入、$40/百万输出（较 5.1 降 20%），Fast Mode 2.5× 速度、$16/$80。官方基准：FrontierCode 2.0 Xhigh 49.1%、FrontierSWE v2 69.9%、Terminal-Bench-Science 0.1 74.6%（Mythos 75.3%）、OSWorld 2.1 89.3%、RoboDojo Sim 64.9%（Fable 5.1 仅 27.6%）、HLE 74.2%、BenchCAD 2.1 83.5（Max，Opus 5.5 为 65.3）。已上线 AWS、Google Cloud、Microsoft Azure。[Source: Anthropic, 2026-11-09]

2.2 Agent 架构与协议

协议治理MCP / A2A 统一到 Linux Foundation 治理框架。2026-08-17，Google 的 A2A 协议正式加入 Linux Foundation 旗下 Agentic AI Foundation（AAIF），与 Anthropic 的 MCP 共享同一开放治理框架，250+ 成员机构、三大云巨头与主要模型厂商共同参与；MCP 规范最新为 2026-07-28 第 5 版（无状态架构，移除 SessionID 与 initialize 握手）。两者分层配合：MCP 解决「Agent 如何用工具」，A2A 解决「Agent 如何找 Agent」。[Source: CSDN（需核实原文）, 2026-08-17；百度百科（需核实原文）, 2026-07-28]

AnthropicMessage Threads 公测（需核实原文）。Message API 的 Message Threads 进入公开测试：首轮提交完整对话 + system + tools，后续仅发新消息与上一轮 response ID，处理 50 万至 100 万 token 长对话时首 token 响应延迟中位数约降 35%。该机制直接服务于长程 Agent 会话的上下文成本与延迟。[Source: 博客园（需核实原文）, 2026-11-02]

CursorAgent SDK 正式发布（2026-10-20）。以「代码文件夹」形式定义智能体：instructions.md 即提示，tools/ 为模型可调用操作，skills/ 存按需加载流程，mcp-connections/ 接入 MCP 工具，channels/ 定义消息接收与回复渠道；支持 GitHub / GitLab / Bitbucket PR 事件、Slack 提及、Webhook 与 cron 唤醒，并内置评估（agent-sdk eval）与一键部署。[Source: Cursor Changelog, 2026-10-20]

编排框架本周 LangGraph / AutoGen / CrewAI 无重大版本发布（媒体口径显示 LangGraph 占多 Agent 编排 90%+ 份额、MCP 月下载量破 9700 万，均非本周数据，仅作生态背景）。[Source: CSDN（需核实原文）, 2026-11]

定价Fable 5.2 标准价 $8/$40，较 5.1 降 20%。Fast Mode 2.5× 速度、$16/$80；官方称 Medium effort 下 Fable 5.2 与 Opus 5.5 Max 档同分（FrontierCode 45.3% vs 45.5%），单任务成本约为后者一半；Low effort 下 HLE 与 Opus 5.5 顶配同分、成本不足十分之一。[Source: Anthropic, 2026-11-09]

3.2 编码基准与工作流

SWE-bench VerifiedOpenAI 2026-02-23 弃用。审计 138 道 o3 未稳定解出的题目，发现至少 59.4% 存在测试设计或问题描述缺陷（35.5% 过严测试、18.8% 过宽测试、5.1% 杂项），使功能正确的提交被拒；同时全部受测前沿模型均能复现原始 gold patch 或逐字问题描述，表明训练污染。OpenAI 已停止报告该基准并建议转用 SWE-bench Pro。[Source: OpenAI, 2026-02-23]

SWE-bench ProOpenAI 2026-07-08 审计后撤回推荐。731 题公开集中，自动数据点分析标记 200 题（27.4%）、人工标注 249 题（34.1%）存在损坏，四类问题为过严测试、提示不足、测试范围过窄、误导提示；前沿模型通过率 8 个月内从 23.3% 升至 80.3%。OpenAI 撤回此前采用 SWE-bench Pro 的建议。[Source: OpenAI, 2026-07-08]

Terminal-Bench审计约 30% 问题后修复为 2.1（2026-11-05）。论文《Benchmarks as Software》提出「基准维护债」概念，对 Terminal-Bench 2.0 做持续验证工作流审计，发现约 30% 问题并发布修复版 2.1：准确率整体 +10pp 以上、榜单排名最多变动 3 位（Spearman rho 0.958）。研究还显示资源预算本身是测量规范的一部分——延长时间限制可闭合 GPT 5.4 上 20pp 的 harness 差距、将 GPT 5.4 mini 的 30pp 差距压缩至 5pp。[Source: arXiv:2611.08417, 2026-11-05]

工作流Agent 从「写代码」转向「交付可运行系统」。Cursor Build Live Apps、GitHub Copilot Agent Merge、Cognition 分级定价均指向同一趋势；Anthropic 官方称其核心代码库中超过 90% 的合并变更由 Claude 编写（含人类指导）。[Source: Anthropic, 2026-11-09；Cursor, 2026-11-05]

Stanford HAIAI Index 2026：组织 AI 采用率 88%；GenAI 三年人口采用率 53%；4/5 大学生使用 GenAI；消费者价值约 $1720 亿/年。[Source: Stanford HAI, 2026-04-13]

Gartner2026 年全球 AI 模型与平台支出预计 $642.52 亿（+63.4%），其中 GenAI 模型 +117%、DSLM +210%（媒体转述，需核实原文）。[Source: 17173（转述 Gartner，需核实原文）, 2026-07-20]

六、风险与不确定性

  • 来源可靠性。Meta Muse Ember、腾讯混元 Hy4、NVIDIA GR00T 2 的官方一手页面未直接取到，数据来自媒体转述（钛媒体、腾讯云社区、网易），引用须回官方页二次核验；Gartner 支出数据、OpenAI 融资、Dropbox 与 Palo Alto Networks 交易均为媒体转述；Anthropic 财务细节（估值、收入）未以 S-1/A 原文核对。
  • 反向证据。Menlo Ventures 为 VC 机构自研估算，非官方统计；其「前沿实验室占 69% 部署支出」与「开源占 19% token 份额」两种叙事并存，集中化与开源崛起并不矛盾但需分层解读。Fable 5.2 全部基准为 Anthropic 自报，第三方复现有限。
  • 数据口径。SWE-bench Verified 的「退役」系 OpenAI 单方决定，SWE-bench 官方仍托管该榜单；企业 AI 支出（Menlo，含基础设施与应用）与 Gartner「AI 模型与平台支出」口径不同，不可相加；「部署 vs 构建」为 Menlo 自定义分类。
  • 基准自报与缺陷。FrontierCode / FrontierSWE / Terminal-Bench-Science 等分数多为厂商自报；Terminal-Bench 审计显示基准缺陷可致准确率 +10pp、排名变动 3 位，资源预算（时间限制）本身即可改变结论（GPT 5.4 上 20pp 差距可被闭合）。
  • 预测局限。OpenAI 融资估值、收购交易、Anthropic 财务数字均为媒体转述，非官方确认；任何【预测】均应视为带不确定性的线索，不应与已核验事实混用。

七、对 Agent Dev 的可执行启示

  1. 把「多智能体编排」纳入模型选型维度。条件：长程、可分解、需并行推进的任务。判读：Fable 5.2 官方演示协调 1000+ 子智能体 8 天构建操作系统，并支持 Orchestrator / Advisor 角色分工——编排能力正成为继推理、编码之后的第三选型维度。框架性含义：架构设计应预留「主 Agent 委派 + 子 Agent 执行」的分层，而非单 Agent 长上下文硬扛。风险提示：官方演示数据，第三方复现有限；子智能体协调成本与失败恢复机制尚未公开。[推断]
  2. 重建编码评估基线，别再用单一榜单做选型。条件：用基准成绩评估或采购编码 Agent。判读：SWE-bench Verified 已因 59.4% 测试缺陷与训练污染被 OpenAI 弃用，SWE-bench Pro 亦被审计出约 30% 损坏并撤回推荐，Terminal-Bench 2.1 修复后排名仍可变 3 位——单一榜单已不可信。框架性含义：优先用真实仓库任务 + 自建验证集，并固定资源预算（时间/上下文）后再比较。风险提示：自建集仍有维护成本，且需防范任务泄露。[推断]
  3. 评估「Harness as a Service」以降低基础设施成本。条件：长程 / 异步 Agent 任务、缺乏自建沙箱与运维能力。判读：Kimi Hosted Agents 把沙箱执行、上下文管理、工具编排、权限控制、任务恢复、审计留痕作为云服务交付，按量计费；企业可叠加 Inference Hook 做推理前安全检查。框架性含义：Agent 基础设施正从「自建」转向「采购」，选型时须把安全边界（数据外泄面、自托管选项）置于成本之前。风险提示：供应商锁定与数据合规；模板化能力可能限制深度定制。[推断]
  4. 按任务层级分配模型，把成本压到 1/3。条件：工具调用、路由、信息抽取等高频子任务。判读：Muse Ember 以约 1/3 单任务成本追平 Haiku 5.5，Fable 5.2 在 Medium effort 下与 Opus 5.5 Max 同分而成本约一半——「小模型做执行、大模型做编排」的分层定价正在成型。框架性含义：建立「任务难度 → 模型档位」的路由策略，并跟踪 cache reads（可占 Agent token 95%+）对会话成本的影响。风险提示：Muse Ember 数据为媒体转述，能力上限待核实。[推断]
  5. 跟踪 Agent token 经济学变化，重估上下文管理策略。条件：构建长上下文、多轮 Agent 应用。判读：Agent 已占 OpenRouter 80% token、cache reads 可占单会话 95%+，Message Threads 等机制把长对话首 token 延迟降约 35%——上下文成本结构正在变化。框架性含义：把「上下文压缩 / 缓存命中 / 会话复用」作为一等优化目标，而非仅优化单次调用。风险提示：Menlo 为 VC 估算，cache 占比随架构差异较大。[推断]
