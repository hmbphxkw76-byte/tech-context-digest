# 05 · 复验与报告（verify）

> **阶段**：6–7。**上游**：`04-repair.md`。**下游**：无（终点）。
>
> **目标**：复验修复效果、做回归检查、计算健康度、产出确定性报告。

---

## 一、复验三步

### 1.1 重跑机器判定

重跑 `02-evaluate.md` 阶段 2 的全部命令，记录退出码与 `[E]`/`[W]` 计数，与修复前对比：

- 错误项只应减少，不应增加；
- 警告项可减少或持平。

### 1.2 语义复评

- 重算 21 项指标（口径见 `../rubric.md`）。
- 重跑 15 类场景判定，统计残余：`residual_p0` / `residual_p1` / `residual_p2`。

### 1.3 回归检查

- `new_issues` = 本轮复评发现、且修复前不存在的问题数。
- `new_issues` 必须为 0；否则判定修复引入新问题，回滚或修正后再复验。
- 连续两轮 P0 不下降 → 停止自动修复，输出待复核清单。

---

## 二、健康度计算

- 维度健康度 = 达标指标数 / 指标总数 × 100%。
- 总体健康度 = 四维均值。
- 写入 `verification.health`。

| 条件 | gate |
|---|---|
| P0 = 0 且 总体健康度 ≥ 90% | `pass` |
| P0 = 0 且 总体健康度 < 90% | `conditional-pass` |
| P0 > 0 | `fail` |

---

## 三、报告结构

产出 `engine/report-audits/quality-audit-<YYYY-MM-DD>.md`，结构如下：

```markdown
# 内容质量审计报告 @ <YYYY-MM-DD>

## 一、结论
- 门禁：pass / conditional-pass / fail
- 总体健康度：<数值>（四维：完整性 / 准确性 / 一致性 / 关联性）
- P0 / P1 / P2 残余计数

## 二、盘点摘要
- 业务线 / 报告 / 提示词 / 登记册 / 模板 / 词汇词条计数

## 三、机器判定结果
- 工具 × 退出码 × [E]/[W] 计数表

## 四、语义判定结果
- 15 类场景命中表（场景 × 级别 × 计数）
- 维度指标明细（指标 × 实测 × 阈值 × 达标）

## 五、修复记录
- 修复表（id / 场景 / SOP / 目标 / 动作 / 状态）
- 待人工复核清单

## 六、回归检查
- 新增问题数 / 结论

## 七、既有遗留（LEGACY）
- 不重复计入健康度的历史问题清单

## 八、附录
- 结构化清单路径（quality-manifest-<date>.json）
```

同时产出 `engine/report-audits/quality-manifest-<YYYY-MM-DD>.json`，符合 `../manifest.schema.json`。

---

## 四、确定性要求

- 报告正文**不写生成时刻**（`generated_at` 仅存于 JSON，且跨轮比对时归一化剔除）。
- 同内容必须产出同字节报告（无随机序、无时间戳）。
- 表格按固定键排序（场景 ID、指标编号、文件路径）。

---

## 五、告警

| 情况 | 动作 |
|---|---|
| gate = fail | 创建 issue（label: `quality-audit`），附待人工复核清单 |
| 连续两轮健康度下降 | 报告中标记趋势异常 |
| 回归 fail | 立即回滚，报告中记录原因 |

---

## 六、终止

- 输出报告与 manifest 后结束。
- 若存在待人工复核项，明确列出，不阻塞交付。
