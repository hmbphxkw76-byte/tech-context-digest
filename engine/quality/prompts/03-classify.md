# 03 · 混乱场景分类判定（classify）

> **阶段**：4。**上游**：`02-evaluate.md`。**下游**：`04-repair.md`。
>
> **目标**：把阶段 2–3 的原始信号归入 15 类场景，定级排序，产出修复队列。

---

## 一、分类口径

对每条原始信号，按 `../chaos-taxonomy.md` 的「判定特征」归类。判定特征必须全部可观测；无法归类的信号标 `UNCLASSIFIED` 并说明，不得强行归类。

| 场景 | 触发信号（示例） | 级别 |
|---|---|---|
| C01 | 跨报告同指标数值不同且无口径说明 | P0 |
| C02 | 归一化相似度 ≥0.9 且无增量 | P1 |
| C03 | 结论缺前提 / 证据链断裂 | P1 |
| C04 | 报告在业务目录外 / 内容主题不符 | P0 |
| C05 | 必填字段空 / 必填节缺 / 来源缺 | P0 / P1 |
| C06 | 同报告前后表述冲突 | P0 |
| C07 | 数值无来源 / 死链 / 媒体未标注 | P0 |
| C08 | 多口径静默择一 | P1 |
| C09 | `href` 无 `id` / 路径不存在 | P0 |
| C10 | 阈值三处不一致 | P0 |
| C11 | 节数 < 骨架 / 缺页头导航 | P0 |
| C12 | 术语多写法 / 与词库不符 | P1 |
| C13 | 数据超时效 / 未标滞后 | P1 |
| C14 | 漂移色 / 非 canonical 类名 / 缺 a11y | P1 |
| C15 | region 不在 sector 之前 | P0 |

---

## 二、定级规则

1. 指标越界即按 `../rubric.md` 的级别定级（P0 / P1 / P2）。
2. 同一对象命中多场景：取最高级别；修复时按场景分别记录。
3. 无法达到阈值但无明确场景：归 `C05`（信息缺失）或 `C03`（逻辑断层），并说明。
4. 已知既有遗留（如历史报告缺免责声明）单独分组为 `LEGACY`，不重复计入健康度，但须在报告中列出。

---

## 三、排序规则

修复队列排序：

```
P0 优先于 P1 优先于 P2；
同级：影响面（涉及对象数）× 修复成本（低→高）升序；
内容增删改类（SOP-02 / 03 / 06 / 08 / 10）排在规则型之后。
```

---

## 四、产出

- `findings[]`：按队列排序，字段同 `02-evaluate.md` 第三节。
- 分组统计：`by_scenario` / `by_severity` / `by_dimension` / `legacy`。
- 修复队列：`queue[]`（finding id + sop + 目标 + 级别）。

---

## 五、纪律

- 每条 finding 必须有场景 ID 与 SOP 条款。
- `LEGACY` 组不得被自动修复（除非用户显式授权）。
- 不修改文件（本阶段只读）。
