# 多主题提示词库（engine/vocabulary/prompts）

> **定位**：与词汇库同库管理的**可复用提示词层**。每个内容主题（`content/<theme>/`）对应一个提示词目录，提示词与术语表（`engine/vocabulary/data/<theme>/terms.md`）**同主题对齐**，随词条同步维护。
> **目标**：以「全面消除信息差」为导向，把「术语一致、来源可核验、边界明确、缺口显式」固化为可直接复制使用的提示词，避免泛化、重复、语义漂移与遗漏。
> **维护入口**：主题注册表 `config/topics.json`；词条变更走 `script/vocab_tool.py import`；提示词正文为人工维护，术语/同义表达以词库为单一事实源。

## 二、设计原则（信息传播最佳实践）

| # | 原则 | 在提示词中的落地 |
|---|---|---|
| P1 | 术语一致 | 正文与标题使用词库「词条」作规范形，首次出现给「同义/近义表达」；不得自造同义词 |
| P2 | 信源可核验 | 要求逐点给出「机构 · 周期 · 发布日期 · 核验状态」，无来源即标「需核实原文」 |
| P3 | 事实与推断分离 | 输出区分「已核验 / 部分核验 / 推断 / 假设」；推断必须给机制链 |
| P4 | 边界显式 | 每条提示词声明「适用 / 不适用」，不越界给具体买卖价位、法律意见等 |
| P5 | 缺口显式 | 输出「信息缺口清单」，无法核实须写成可核验陈述，不补值、不外推 |
| P6 | 受众适配 | 按「工作 / 生活 / 研究 / 学习」四场景给不同深度与句式，不混用 |
| P7 | 单一事实源 | 术语定义只指向词库，提示词不复制定义正文，避免复述漂移 |

## 三、文件结构

```
engine/vocabulary/prompts/
├── README.md                      # 本文件：总览 / 分类 / 原则 / 扩展
├── <theme>/
│   ├── README.md                  # 主题库：定义与边界 / 术语对齐 / 场景词汇 / 提示词索引 / 核验 / 信息缺口
│   ├── prompt-work-brief.md       # 工作场景（从业者快速研判）
│   ├── prompt-life-brief.md       # 生活场景（个人决策与避坑）
│   ├── prompt-research-brief.md   # 研究场景（系统调研与综述）
│   └── prompt-learning-brief.md   # 学习场景（入门到进阶路径）
```

- 空主题（教育 / 国际 / 政治 / 社会）交付 `README.md` + `prompt-skeleton.md`（骨架），词条采集后补全。
- 提示词文件命名：`prompt-<slug>.md`（slug ∈ `work-brief` / `life-brief` / `research-brief` / `learning-brief` / `skeleton`）。

## 四、使用方式（复用流程）

1. **选主题** → 读该主题 `README.md` 的「定义与边界」，确认问题在覆盖范围内。
2. **选场景** → 按工作 / 生活 / 研究 / 学习选对应 `prompt-*-brief.md`。
3. **复制正文** → 将「提示词正文」代码块整段复制使用；`{{变量}}` 按主题词库与当前任务填充。
4. **核对术语** → 输出中的术语以词库规范形为准；同义表达不得引入词库外新词。
5. **回填缺口** → 把本次发现的「信息缺口」追加到主题 `README.md` 第六节，必要时走词库 `import`。

## 五、核验口径

| 维度 | 标准 | 落地位置 |
|---|---|---|
| 定义清晰度 | 主题定义含「覆盖 / 不覆盖 / 与相邻主题界线」 | 各主题 README 第一节 |
| 覆盖完整性 | 词库全部分类在「术语对齐表」出现；核心术语有同义表达 | 各主题 README 第二节 |
| 表达精准度 | 每条提示词有「适用 / 不适用 / 边界 / 误解 / 缺口」 | 各提示词文件 |
| 无重复 | 术语定义不复制；提示词之间场景不重叠 | 各主题 README 第四节索引 |
| 无漂移 | 术语以词库规范形为准，缺口显式 | 全文 |

## 六、信息缺口（跨主题）

| 缺口 | 影响 | 补采建议 | 状态 |
|---|---|---|---|
