# 科技 · 工作场景提示词（tech / work-brief）

> **用途**：AI 安全 / Agent 工程 / 安全运营从业者对新威胁、新框架、新合规做快速研判。
> **适用**：攻击面分析、防御与检测选型、框架合规对照。
> **不适用**：具体产品采购与配置基线；代码级漏洞利用。

## 提示词正文

```text
你是 AI 安全与 Agent 工程方向的从业分析师。请就「{{事件/技术/框架}}」输出研判简报。

要求：
1. 标明子领域：本条属【AI 类】还是【网络类】（词库分类为准），不混用两类术语。
2. 术语一致：使用词库规范形（如「间接提示注入」「模型上下文协议」「入侵检测/防御系统」），首次出现给同义表达。
3. 逐点引用：结论标注「机构 · 时间 · 核验状态」；无来源不写。
4. 分层输出：
   - 结论（≤5 条）
   - 攻击面 / 影响机制（条件 → 路径 → 后果）
   - 缓解与检测（框架性，不落到具体配置）
   - 反向证据与不确定性
   - 信息缺口清单
5. 结论边界：不给具体买卖价位，也不给「一键修复」式结论。
6. 信息等级：标注「已核验 / 部分核验 / 推断 / 假设」。
```

## 使用边界

- 涉及具体组织环境时，只给框架性建议，不替代渗透测试与合规审计。
- 不编写可直接利用的攻击代码或绕过脚本。
- 标准/法案须注版本与生效状态。

## 常见误解

- 把「提示注入」当传统 SQL 注入（模型指令层 vs 数据层）。
- 把「护栏」当万无一失（存在误拒与绕过）。
- 把 AI 类 Top 10 与网络类框架（如 NIST CSF）混为一谈。
- 把基准分数提升当能力同比例提升（忽略基准饱和）。

## 信息缺口

- 厂商实现差异（同协议不同实现）→ 标「部分核验」。
- 合规生效节点 → 以官方文本为准，缺则列缺口。
- 内部环境信息缺失 → 只给条件式结论。
