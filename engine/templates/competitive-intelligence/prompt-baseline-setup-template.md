# 基线报告类型模板（竞争情报监测型）

> **用途**：竞争情报监测型业务线**建立期**的报告类型模板。产出首期竞争格局基线报告与配套竞品档案库，作为后续所有周期更新的对比锚与制度基础。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置（`{地区}/{业务类型}/prompts/business-config.md`）。质量规则见通用基座与通用规范；本文件规定竞争情报监测型基线报告的差异项与结构骨架；冲突时以业务提示词为准。

---

## 一、基线报告的特殊定位（与周期更新的差异）

1. **对比锚属性**：基线报告是后续所有周期更新的对比锚；竞争格局分层、竞品档案卡结构与口径裁决规则须被后续更新完整继承。
2. **无上期报告**：不读取 `{{PREVIOUS_REPORT_PATH}}`；「已修正事实清单」为空，产生修正后逐条补记（格式见通用基座第五节）。
3. **档案库首建**：运行后建立竞品档案库（逐家档案卡：定位 / 产品 / 定价 / 渠道 / 组织 / 近期动作，每格附 `[来源, 日期]`），并从基线报告提取监测竞品清单与信号规则回写 `{{REGISTRY_PATH}}`；prompt 模板内严禁填写活值。
4. **公开信息边界**：只采集公开合法信息（官网、财报、招聘、应用商店、专利、公开社媒）；不使用非公开渠道，不伪造无法核实的动作记录。
5. **产出联动**：基线产出后，`{{BASELINE_REPORT_PATH}}` 即指向本报告；后续周期提示词的该变量值保持不变。

## 二、结论边界（本类型的特别声明）

竞争情报报告对竞品动作只做**事实记录与影响提示**，不做「对手必然失败 / 必然成功」式断言；威胁 / 机会提示须标注「判断 / 推断」，与事实数据明确分离。

## 三、报告结构骨架（九节固定顺序）

> 九节固定顺序为本类型通用骨架；业务提示词可细化节标题措辞，但**不得增删节、调整顺序**。已产出基线报告的节标题为该业务线的固化锚，后续报告逐字继承。

| 节 | 模块 | 核心定位 / 必填内容 |
|---|---|---|
| 1 | 执行摘要 | 核心判断（编号条目，每条含数据、口径、来源）+ 竞争格局一句话定位 + 本期动作热点综述 + 来源与时点。 |
| 2 | 监测机制设计 | 数据流（来源层 → 档案库层 → 动态矩阵层 → 输出层）；监测节拍（月度主更新 + 事件触发升级）；监测竞品清单与入选标准。 |
| 3 | 竞争格局总览 | 玩家分层表（直接 / 间接 / 潜在进入者，含判断依据）；市场集中度与份额口径（多口径并列不合并）；格局演变方向（标「推断」）。 |
| 4 | 竞品档案首建 | 逐家档案卡（定位 / 产品矩阵 / 定价 / 渠道 / 组织与人事 / 近期动作），每格附来源与日期；未能核实的字段注明「待核实」，不补值。 |
| 5 | 动态矩阵与信号规则 | 动态矩阵（维度 × 玩家）；信号规则表（编号：监测对象 / 触发条件 / 确认标准 / 动作）；阈值与规则由业务配置定义。 |
| 6 | 来源与核验治理 | 来源分级表（按通用基座第四节实例化）；口径优先级裁决规则；首期核验审计（未核验项：项目 / 状态 / 处置）。 |
| 7 | 风险与盲区 | 情报盲区（渠道覆盖缺口、时滞、无法观测的私有动作）；对自身判断的反向声音（高亮块，至少 2 条）。 |
| 8 | 交付物与后续运行方式 | 交付物表（交付物 / 路径形式 / 内容）；月度与事件触发的运行方式。 |
| 9 | 参考来源清单 | 按来源分级分组，完整 URL，逐点可回溯。 |

## 四、档案库与登记册联动

- 竞品清单与信号规则编号由业务配置定义；基线报告须完整呈现「监测竞品 × 优先信息渠道」追踪表，运行后逐项回写 `{{REGISTRY_PATH}}`。
- 每格活值附 `[来源, 日期]`；未核实项注明「待核实」，不补值、不外推。

## 五、图表与渲染（基线期）

- 交付格式：Markdown 源稿 + 同目录自包含 HTML（经 `engine/tools/md2html.py` 同步生成）。
- HTML 须通过 `engine/tools/lint_reports.py`：表格标签配对为强制项。
- 基线导航采用简化锚点目录，不强制升级为 `.report-nav`。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 九节齐全、顺序正确、编号连续；节标题为该业务线固化锚
- [ ] 全部监测竞品档案卡 covered，每格附来源与日期
- [ ] 事实与判断分离；威胁 / 机会提示标「判断 / 推断」
- [ ] 信号规则全部登记，编号与动态矩阵一致
- [ ] 仅使用公开合法信息；信息边界声明已写入
- [ ] 档案库与登记册已首建并回写
- [ ] HTML 通过 lint（标签配对）

## 七、维护规范

- **修订触发条件**：结构变更、竞品清单调整、信号规则变更、来源清单变更、命名规则变更。
- **变更流程**：先改本类型模板 → 同步业务提示词 → 更新版本记录 → 评估该类型全部周期提示词联动。
- **固化保护**：已产出基线报告不得改动；结构变更只影响后续新基线。
