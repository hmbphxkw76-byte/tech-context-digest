# 基线机制建立类型模板（行业趋势周报型）

> **用途**：行业趋势周报型业务线**首期（基线期）**的报告类型模板。基线期不出周报正文，而是建立周报的运行机制：定位受众、主题矩阵、来源分级、台账与报告固定结构。基线一经产出即为锚，变更须走维护规范并联动评估全部周期提示词。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；冲突时以业务提示词为准。

---

## 一、基线期定位

- **产出物是机制文档，不是报告正文**：九节机制文档落盘 `reports/{{YYYY-MM}}_baseline_report.html`，作为全部后续周报的结构与结论锚。
- **正常运行永不重跑基线**。仅两种情形允许重建：台账与报告全部丢失（灾难恢复）；八节固定结构经维护规范批准变更。

## 二、九节固定结构（顺序、标题逐字固化，不得增删改）

1. **周报定位与受众**：监测主题一句话定义；受众画像与视角声明；结论边界（只给条件 → 判读 → 框架性含义 → 风险提示）。
2. **监测范围与主题矩阵**：三大主题板块定义（固定 3 块，对应周报 s2–s4）、每块的监测对象与不覆盖范围。
3. **数据来源与分级**：按通用基座四层来源分级实例化机构清单（官方一手 / 行业机构 / 挂牌门户 / 媒体转述）与 `{{SOURCE_LANGUAGE_RULE}}`。
4. **运行变量与台账协议**：变量清单（见通用基座第二节）；`{{REGISTRY_PATH}}` 登记载体格式与工作表 / 章节定义。
5. **报告固定结构与命名**：八节周报骨架逐字定义（本周要点 Top5 / 主题板块 ×3 / 数据看板 / 风险与不确定性 / 可执行启示 / 参考来源）；命名 `{{YYYY-MM-DD}}_weekly`（日期 = 数据截止日）。
6. **触发器与节拍设计**：触发器清单（`事件 → 受影响板块`）；空窗与 T+1 处理规则；归档保留策略（weekly 12 期）。
7. **质量自检与更新协议**：通用基座第九节 + 类型模板第六节自检项；已修正事实清单格式与防回退规则。
8. **风险与盲区**：来源反爬 / 转述失真 / 基准自报等已知局限与缓解。
9. **交付物与后续运行方式**：交付格式声明（md+HTML 双格式或纯 HTML）；校验命令清单；首次周报启动条件。

## 三、基线期执行步骤

1. 完成监测范围与主题矩阵调研（板块定义须覆盖业务配置受众的决策需求，且互不重叠）。
2. 完成来源清单与发布节奏调研（逐机构记录官方页 URL、发布频率、语言）。
3. 首建台账（数据看板追踪表 / 已修正事实清单 / 来源清单 / 触发器清单 / 版本记录）。
4. 撰写九节机制文档并落盘；八节周报骨架在机制文档第五节逐字固化。
5. 将业务配置的 `{{BASELINE_REPORT_PATH}}` 指向本报告。

## 四、输出与命名

- 文件名：`reports/{{YYYY-MM}}_baseline_report.html`（月份 = 机制建立月）。
- 九节结构、标题逐字固化；基线报告保留简化锚点导航（非 `.report-nav`）。
- 基线报告常驻 `reports/` 顶层，不进入归档。

## 五、质量自检（在通用基座第九节之上追加）

- [ ] 九节结构与本模板第二节逐字一致
- [ ] 主题矩阵三块定义完整、互不重叠、覆盖受众决策需求
- [ ] 来源清单逐机构有官方 URL 与发布节奏
- [ ] 台账已首建且工作表 / 章节定义与机制文档第四节一致
- [ ] 八节周报骨架已逐字固化于机制文档第五节
