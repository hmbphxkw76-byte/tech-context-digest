# 周期更新类型模板（行业趋势周报型）

> **用途**：行业趋势周报型业务线**运行期**的报告类型模板。以公开来源为依据、以上一期周报为对比锚，完成「采集 → 核验 → 看板刷新 → 可执行启示」闭环；固定节拍为周（数据截止日为锚的 ISO 日期命名）。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；本文件规定行业趋势周报型周期更新的差异项与方法框架；冲突时以业务提示词为准。

---

## 一、节拍设计

| 节拍 | 定位 | 触发条件 | 输出 |
|---|---|---|---|
| 周期 | 主更新节拍：主题板块逐块更新 + 数据看板刷新 | 每周常规窗口 | 完整八节周报（结构逐字继承基线） |
| 事件触发 | 升级更新：命中业务配置触发器时对应板块重点刷新 | 任一触发器命中 | 周报内对应板块重点更新，不单独出件 |

- **触发器**清单由业务配置维护（格式：`事件 → 受影响板块`）；重大事件（重大发布 / 监管动作 / 安全事故 / 融资并购）须当期核实并升级，不等待下周窗口。
- **空窗处理**：本周无实质变化时降级为核验轻运行（核对上期结论与来源时效，登记册标注「截至 {{CURRENT_DATE}} 无更新」），不得为制造变化而虚构变化；T+1 情形（与上期数据截止日仅隔 1 日）在报告头部明确标注。

## 二、更新协议

1. **读取锚**：每次运行必须读取 `{{PREVIOUS_REPORT_PATH}}` 与 `{{BASELINE_REPORT_PATH}}`，继承八节结构、口径裁决与全部已核实结论。
2. **已修正事实清单**：逐条继承并在产生修正后追加（格式见通用基座第五节），严禁重新引入已被推翻的说法；无来源不得入清单。
3. **台账闭环**：运行前从 `{{REGISTRY_PATH}}` 读数据看板活值 → 逐项核验 → 运行后回写；每期逐项填写「是否更新」，未变动项注明「截至 {{CURRENT_DATE}} 无更新」。
4. **多源交叉验证**：关键事实须至少 2 家独立来源确认；媒体转述标「需核实原文」并回官方页校验；预测类数字标【预测】并注明来源与置信度。
5. **口径纪律**：同一指标多口径并列呈现，不平均、不静默择一；跨机构数字不可相加；反方证据（对核心结论的公开质疑）必须收录进「风险与不确定性」。

## 三、各模块更新要点框架

业务提示词按以下框架实例化「要动态获取什么」：

- **本周要点 Top5**：本周最重要 5 条趋势，每条 = 结论一句话 + 关键数字 + 来源；【事实】与【预测】显式标注。
- **主题板块 ×3**：板块划分由业务配置「主题矩阵」定义（固定 3 块，不得增删）；每块按「新事实 → 机制解读（推断，显式标注）→ 对受众的含义」组织。
- **数据看板**：指标 × 上期值 × 本期值 × 变化 × 来源 × 口径，逐行登记并与台账联动。
- **风险与不确定性**：来源可靠性、反向证据、口径冲突、基准自报等系统性局限。
- **可执行启示**：面向业务配置定义受众的行动建议（标「推断」），只给「条件 → 判读 → 框架性含义 → 风险提示」。

## 四、输出与命名（与仓库工具链对齐）

| 节拍 | 文件名（业务目录相对路径） | 版本号 |
|---|---|---|
| 周报 | `reports/{{YYYY-MM-DD}}_weekly.html`（日期 = 数据截止日） | 写入报告内（vYYYY.MM.DD） |

- 文件命名遵循仓库统一约定（`engine/tools` 按此识别）；**日期为数据截止日而非执行日**，跨月 / 跨年不换名。
- 交付格式由业务配置声明：默认 md 源稿 + 同目录自包含 HTML；富样式手写 HTML 的业务线在业务配置声明「纯 HTML 交付」，md 源稿移存 `sources/`（不参与 `md2html.py` 自动转换，防止覆盖手工渲染）。
- HTML 必须通过 `engine/tools/lint_reports.py`（表格标签配对强制）与 `engine/tools/compliance_check.py`（八节骨架）。
- 周期报告按归档保留策略执行（weekly 保留 12 期）。

## 五、执行方式（建议）

1. 按信息渠道并行启动研究子代理（官方博客 / 监管与标准机构 / 研究机构与数据库 / 权威媒体），全部限定公开来源、逐点引用 URL。
2. 子代理返回后由主代理读取 `{{PREVIOUS_REPORT_PATH}}` 做差异合并，继承已修正事实清单，应用业务配置的板块更新要点。
3. 冲突信息保留双份引用并列呈现；无法核实项单列「待复核清单」。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 八节结构与基线逐字一致（顺序、编号 s1..s8 不变）
- [ ] 已修正事实清单已继承并续写，无回退
- [ ] 数据看板逐行核对并回写台账；prompt 模板无硬编码活值
- [ ] 关键事实多源确认；转述项已标注「需核实原文」；预测项已标【预测】
- [ ] 反方证据已收录；口径冲突并列呈现
- [ ] HTML 通过 lint + 合规校验（八节骨架 + 顶部导航）
