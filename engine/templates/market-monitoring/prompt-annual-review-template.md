# 年度报告类型模板（市场指标监测型）

> **用途**：周期性（每年）执行年度策略复盘的类型模板。产出年度 HTML 报告 + 新版指标台账。目标不是市场评论，而是：① 复盘全年；② 检验预测；③ 重置长期基线；④ 校准信号；⑤ 更新情景；⑥ 更新台账。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；年度差异见本文件；冲突时以业务提示词为准。

---

## 一、年度报告的周期特性与命名规则

1. **命名规则**：报告用「被复盘年份」，台账用「生效年份」。例：2026 年度复盘 → `reports/{{YEAR}}_annual.html` + `data/{registry_name}_{{NEXT_YEAR}}-01.xlsx`。
2. **预测 vs 实际偏离**：偏离度 =（实际 ÷ 对照）− 1；凡绝对值 >30%，必须重设假设，并在报告中列出「重设了哪三项假设」。机制首年无自有年初预测时，用三类替代对照（机构预测 / 计划 / 官方目标），明确「不做事后拟合」。年化值标注为「机制自算」，不得伪装成机构发布。
3. **长期基线重置**：人口、FDI、GDP/CPI、利率、供给兑现率等长期锚取最近已发布年度值；年度数据存在 6–9 个月时滞，不得用于月度择时；「实时值」与「年度基准」口径不得混用。
4. **政策框架复核**：政策项清单（编号 G01–Gn）由业务配置定义；仅核验官方页面，未取得条款页的标「未核验」，禁止引用商业中介数值作为事实；官方入口页 ≠ 条款页；政策变更 → 立即重算需求情景。

## 二、机制自检与校准方法（年度特有）

### 2.1 信号规则回测

- 回测全部信号规则：触发过密（>6 次/年）或过疏（0 次/年）须校准。
- 机制运行不足 12 个月时，**如实标注「无法完成频率回测」**，只做「预校准（ex-ante）」，不得伪造触发次数。
- 校准规则（通用）：
  - **持续型规则**：记录「首次进入硬红期 + 持续期数」，不重复计数。
  - **年度型规则**：以「每年 1 期是否可得」为校准标准，不以 0 次判失效。
  - **高频型规则**：保留确认窗，预警红在确认窗内单独展示。
  - **单源 / 媒体转述**：只能记「硬红 · 方向」，标注「完全确认未完成」。
- 计数呈现：核心矩阵计数（红 / 黄 / 绿 / 灰）+ 全部规则的硬红 / 预警红 / 黄 / 绿 / 灰计数 + 硬红中「完全确认」与「方向确认」各几项。

### 2.2 五态定义（通用方法论）

| 状态 | 定义 | 确认要求 | 动作 |
|---|---|---|---|
| 绿灯 | 读数处于支持区间，方向为正 | 无需额外确认 | 维持基线，季度复核 |
| 黄灯 | 读数处于观察区间，方向未定或分化 | 至少 2 期同向 | 提高监测频率，列入观察清单 |
| 预警红 | 越过预警红线，但未满足硬红确认标准 | 至少 1 项确认未完成 | 进入季度专项；补齐数据；不重算长期情景 |
| 硬红 · 方向 | 越过硬红线，≥2 个独立来源方向一致，但双源 / 连续期数仍缺 | 方向确认完成 | 重算对应情景的方向与区间；标注确认缺口 |
| 硬红 · 完全 | 越过硬红线，满足全部确认标准 | 双源 / 连续期数 / 官方原文均完成 | 立即重算情景并更新决策矩阵 |
| 灰灯 | 官方数据缺口，无法判定 | — | 不进入信号合成；列入年度盲区 |

- **阈值重叠处理**：同一指标同时落入黄灯与预警红区间时，按「更严状态优先」处理，并标注重叠区间与判定依据；不得因黄灯区间覆盖而降级。
- 硬红线数值变更须记录版本，不得事后改写。

### 2.3 来源巡检

- 逐条复核官方来源清单的 URL 路径、最近核验时间、最新已发布周期、发布频率变化；记录 404、聚合页替代、停更、版本延迟、降频等情况。
- 明确本次是「桌面巡检」还是「联网复测」；未联网时明确标注。
- 数据盲区每年检查是否补齐；未补齐的写明替代方案。

### 2.4 台账增删

- 新增派生指标或官方指标；合并重复指标；降级仅有二手转载的指标；生成台账新版本（文件名带新年份，写明版本号与变更点）。

## 三、多年情景与决策矩阵（年度特有）

- **公式**：`实际交付/需求 = 计划锚 × 兑现率`。
- 计划锚取跨机构区间（低 / 中 / 高），不得用单点；兑现率取最近半期、上一完整年度、历史区间（运行前从台账读取，不得硬编码）。
- 情景：悲观 = 低计划 × 低兑现率；基准 = 中计划 × 中兑现率；乐观 = 高计划 × 高兑现率。
- 末年无独立计划值时，用长期管道扣除前两年中值后的残差按剩余年份均分推导，标注「误差最大」。
- 利率路径：政策链三条件推演，不赋概率。
- 决策矩阵：至少 4 行，格式「条件组合 → 周期判读 → 框架性含义 → 风险提示」。
- **禁止**：具体买卖价位、仓位建议、点预测伪装成基准。

## 四、报告结构骨架（10 节固定顺序）

| 节 | 模块 | 核心定位 / 必填内容 |
|---|---|---|
| 1 | 年度结论 | 结论先行（一句话周期判断）；证据边界（机制运行几期、目录内有哪些报告、哪些缺失，不虚构序列）；5 条年度结论（按业务维度）；KPI 卡（张数由业务配置规定）；五态计数与核心矩阵；来源注。 |
| 2 | 全年关键数字 | 按业务维度分组四张表，每行含：指标、最新读数、统计周期、性质、来源机构、发布日期、核验状态；指标名称内嵌链接。配套图表 2–3 张 + 图注。 |
| 3 | 预测 vs 实际偏离 | 方法说明；表格：对照项、机构预测 / 计划（A）、实际 / 最新（B）、偏离、>30%、处置、来源与时点；>30% 的三项假设重设；「不做事后拟合」声明。 |
| 4 | 多维年度全景 | 按业务维度逐维展开 + 传导链复盘（哪条链主导；至少一条反向声音；已定价 / 部分定价 / 未定价三行表）。来源注。 |
| 5 | 官方先行指标年度基线 | 官方读数表（编号、指标、最新官方读数、性质、统计周期、发布日期、核验，内嵌链接）；预测分歧并列表；长期基线表（锚 / 新基线值 / 统计周期 / 来源与时点 / 说明）。 |
| 6 | 多年供给情景与决策矩阵 | 方法 + 计划锚 × 兑现率三情景表 + 利率路径 + 决策矩阵 + 边界说明。 |
| 7 | 政策框架与未核验清单 | G01–Gn 表（政策项、市场常见引述仅记录、官方复核结果、状态、含义 / 处置）；未核验清单（下限由业务配置规定）。 |
| 8 | 信号阈值回测与预警红线 | 五态定义 + 三级红线组 + 统计条；全部规则表（编号、对象、等级、预警红线、硬红线、当前读数、距硬红线、状态、确认进度、读数来源）；当前状态计数；校准说明。 |
| 9 | 官方来源巡检 | 来源逐项表（#、机构 / 来源、频率、最近核验、巡检状态、频率变化 / 处置）；数据盲区 n/N 补齐与替代方案（N = 业务配置定义的 P0 盲区类别数）；桌面巡检 / 联网复测声明。 |
| 10 | 台账修订说明 | 版本、基线日、工作表数量、指标数量、信号规则、来源清单、监测日历、基线值的变化；新增 / 合并 / 降级指标；交付空缺；声明为本地版本记录。 |

## 六、新版台账规范框架（工作表由业务配置实例化，通用建议含）

1. 看板（五态计数与预警红线总览）
2. 指标台账（以实际项数为准）
3. 预警红线（全部规则，五态与升级动作）
4. 官方来源清单（含巡检列）
5. 监测日历（含季度红线复核、年度红线校准）
6. 信号规则（全部规则 + 等级 / 阈值 / 当前读数 / 距硬红线 / 触发 / 校准动作）
7. 首期基线值（历史锚，保留）
8. 年度基线（长期锚）
9. 使用说明（版本记录、已知盲区）

- 版本记录写在「使用说明」：版本号 / 基线日 / 生效年份、工作表变化、指标增删、阈值校准、来源巡检列、日历行数；历史记录保留。
- 覆盖输出前已备份旧版；未删除历史报告。

## 七、渲染要求（年度特化）

- 通用规范第 5 节顶部导航强制；锚点与 10 节标题逐字一致。
- 行内链接式来源承载（通用规范第 4 节 B 式）；所有含来源列的表逐行至少 1 个 `href`；KPI 卡全部有链接。
- 媒体转述标注：凡出现媒体转述字样的行，同一行必须有「需核实原文」或「部分核验」说明。
- 口径冲突并列（典型冲突清单由业务配置定义）。

## 八、质量自检（在通用基座第九节之上追加）

- [ ] 10 节齐全、顺序正确；导航锚点与节标题逐字一致、跳转准确
- [ ] 全年复盘项齐全，预测 vs 实际偏离已计算；>30% 偏离已重设假设
- [ ] 官方年度数据与长期基线已取最近已发布值
- [ ] 政策框架复核状态明确（未核验项未引用具体门槛数值）
- [ ] 机制自检完成（回测、来源巡检、盲区、增删指标）
- [ ] 多年情景兑现率取自台账，未硬编码
- [ ] 五态计数与核心矩阵一致；重叠区间按「更严状态优先」
- [ ] 新版台账 `{{OUTPUT_REGISTRY}}` 已生成，工作表数量与版本记录正确
- [ ] 标准列结构逐表核对；媒体转述行全部有「需核实原文」
- [ ] 覆盖输出前已备份旧版；未删除历史报告

## 九、Agent 执行约定（年度特化）

- 台账修改采用增量方式：复制旧表 → 修订 → 另存新版本，不覆盖旧版。
- 不修改只读附件；不创建与任务无关的文件。
- 不得伪造年度触发频次；不得事后拟合「年初预测」。
