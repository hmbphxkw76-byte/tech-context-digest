# 基线报告类型模板（市场指标监测型）

> **用途**：监测机制**建立期**的报告类型模板。产出首期基线报告与配套指标台账，作为后续所有周期报告（月 / 季 / 年）的对比锚与制度基础。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；本文件规定基线报告的差异项与结构骨架；冲突时以业务提示词为准。

---

## 一、基线报告的特殊定位（与周期报告的差异）

1. **对比锚属性**：基线报告是后续所有周期报告的对比锚，不是普通首期报告。其结构、全部已核实结论与口径裁决规则须被后续月 / 季 / 年报告完整继承。
2. **无上期报告**：不读取 `{{PREVIOUS_REPORT_PATH}}`；「已修正事实清单」为空，产生修正后逐条补记（格式见通用基座第五节）。
3. **机制建立文档**：须完整定义数据流、指标体系、信号规则、监测日历与数据治理，不得省略为「纯数据罗列」。
4. **产出联动**：基线报告产出后，`{{BASELINE_REPORT_PATH}}` 即指向本报告；后续周期提示词的该变量值保持不变。
5. **指标台账首建**：运行前从业务配置确认 `{{REGISTRY_PATH}}` 目标路径与格式；运行后建立台账全部工作表（指标台账、信号规则、来源清单、监测日历、首期基线值、使用说明等，数量以业务配置为准）。
6. **首期发布窗口判定**：须明确基线日所处发布窗口位置，列出「应发布但未发布」清单与官方页面依据；时效取舍遵循 `{{FRESHNESS_PRIORITY}}`。

---

## 二、结构维度框架（占位符化）

监测维度由业务配置定义（如四维：价格与成交 / 供需与管道 / 租赁与收益 / 宏观先行）。基线报告须覆盖业务配置声明的**全部维度**，每个维度包含：

- 指标清单与优先数据源
- 官方一手来源 URL 与发布节奏
- 基线日读数 + 口径 + 来源

信号规则（编号如 K01–Kn）由业务配置定义；基线报告中须完整登记其阈值、绿灯 / 黄灯 / 红灯定义、确认标准与动作。

---

## 三、报告结构骨架（业务线按此实例化节标题与内容）

> 10 节固定顺序为通用骨架；业务提示词可细化节标题措辞，但**不得增删节、调整顺序**。已产出基线报告的节标题为该业务线的固化锚，后续报告逐字继承。

| 节 | 模块 | 核心定位 / 必填内容 |
|---|---|---|
| 1 | 执行摘要：结论先行 | 全文浓缩：核心判断（1 段）+ 支撑论据（3 条编号，含数据、口径、来源）+ 先行信号综述（红 / 绿 / 灰灯计数 + 方向）+ 关键数字卡（张数由业务配置规定，每张含指标名、数值、统计周期、来源简称）+ 来源与时点。不展开传导机制、不重复全量数据、不给建议。 |
| 2 | 持续监测机制设计 | 数据流与传导路径（数据源层 → 指标台账层 → 信号规则层 → 决策输出层）；三级监测节拍（月 / 季 / 年，各含目的 / 核心指标 / 输出物）；宏观 → 目标市场的传导链（每条含先行变量 / 中间变量 / 典型时滞 / 验证指标）。 |
| 3 | 多维指标体系与来源 | 维度总表（维度 / 核心指标 / 时序属性 / 主要发布方 / 口径警示）；官方权威来源与发布节奏表（经济指标唯一采信层）；口径冲突标注（高亮块，并列不合并）。 |
| 4 | 首期基线数据（{{BASELINE_DATE}}） | 按维度展开，每子节含「读数 + 口径 + 来源」：序列表、口径警示、结构要点、图。只呈现读数与口径，不做信号判定、不做预测。 |
| 5 | 先行指标判读 | 沿第 2 节传导链合成方向性判断：传导链推导总述 + 信号网格（灯色 + 结论 + 依据数据 + 来源）+ 反向声音（高亮块，至少 2–3 条）。不引入第 4 节之外的新数据。 |
| 6 | 信号规则与决策框架 | 信号规则表（K01–Kn：编号 / 监测对象 / 绿灯 / 黄灯 / 红灯 / 确认标准 / 动作，阈值取自业务配置与台账）；条件化决策框架（条件组合 / 周期判读 / 框架性含义 / 风险提示）；边界说明（高亮块）。只给规则不给本期判定结论；阈值为首期默认参数，须年度回测校准。 |
| 7 | 月 / 季 / 年监测日历 | 日历表（周期 / 时点 / 任务 / 主要来源 / 输出与升级条件）；与登记载体监测日历工作表的对应关系。时点来自第 3 节发布节奏。 |
| 8 | 数据治理：来源分级、口径优先与核验状态 | 来源分级表（按通用基座第四节实例化）；口径优先级裁决规则 + 冲突案例；首期核验审计（明确未核验项：项目 / 状态 / 处置）；来源约束执行结果（高亮块）。 |
| 9 | 风险、局限与监测盲区 | 市场与资产风险（条目式）；本机制的局限（数据缺口 / 发布时滞 / 口径不可比 / 阈值未回测 / 非实时等）。不给风险应对建议。 |
| 10 | 交付物与后续运行方式 | 交付物表（交付物 / 路径形式 / 内容）；运行方式说明。 |

## 四、图表与渲染（基线期）

- 按监测报告通用规范第 2 节执行；基线报告图表数量下限由业务配置规定（覆盖全部维度至少各 1 张）。
- 基线报告导航按通用规范第 5 节「基线特例」执行（简化锚点导航）。

## 五、质量自检（在通用基座第九节之上追加）

- [ ] 全部节齐全、顺序正确、编号连续；节标题与已产出基线报告逐字一致
- [ ] 每节必填内容模块齐全
- [ ] 全部维度（业务配置声明）均 covered，基线读数齐全
- [ ] 信号规则全部登记，编号与第 3 节指标、第 5 节信号网格一致
- [ ] 来源分级与核验状态完整，未核验项已单列
- [ ] 台账已建立：工作表齐全，追踪表与报告一致
- [ ] 基线导航为简化锚点导航（未升级为 `.report-nav`）
- [ ] `{{BASELINE_REPORT_PATH}}` 已在业务配置与各周期提示词中指向本报告

## 六、维护规范

- **修订触发条件**：结构变更、维度调整、信号规则变更、来源清单变更、命名规则变更。
- **变更流程**：先改本类型模板 → 同步业务提示词 → 更新版本记录 → 评估月 / 季 / 年提示词联动 → 自动化记录留痕。
- **版本号规则**：`vMAJOR.MINOR.PATCH`（结构变更 MAJOR，模块增删 MINOR，文字修订 PATCH）。
- **固化保护**：已产出基线报告不得改动；结构变更只影响后续新基线（如年度复盘重置基线时）。
