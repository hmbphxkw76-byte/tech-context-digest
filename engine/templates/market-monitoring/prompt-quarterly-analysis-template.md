# 季度报告类型模板（市场指标监测型）

> **用途**：周期性（每季度）刷新季度分析报告的类型模板。对监测主题做多维全景研判，重算先行信号矩阵与结构红线，重算供给情景，更新条件化决策情景，完成数据治理与下季度观察清单。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；季度差异见本文件；冲突时以业务提示词为准。

---

## 一、季度报告的周期特性

1. **全景研判**：季度报告覆盖业务配置声明的全部维度（如四维），逐维交叉核验行业机构季度报告，区分并列表述不同统计口径（口径清单由业务配置定义，如表观均价 ≠ 同质化价格变动 ≠ 混合调整指数 ≠ 中位价）。
2. **机构获取协议**：季度必查机构的获取路径、更新节奏与缺失处理由业务配置实例化（含 P0–P5 获取优先级、自动化抓取 SOP、缺失时的最小可替代集）。
3. **口径纪律（通用）**：
   - 计划量必须按兑现率折算成实际区间，不得当作交付事实；机构分歧 >20% 必须分轨呈现，不得取中值或合并。
   - 前置量（许可 / 新推盘）与后验量（竣工 / 交付）不得混用单位。
   - 挂牌端与登记端背离超阈值时必须点明「未出清」。
   - 官方定盘与盘中报价严格区分；预测分歧超阈值必须用区间，不得取点值。
   - 不同行政层级统计域（如城市 / 首都圈 / 全国）不得混算。
4. **阈值触发动作（通用）**：许可面积同比超阈值触发中期供给复核；兑现率低于阈值必须重算次年实际交付区间；续约降租占比超阈值触发对应红线。

## 二、方法论骨架（季度特有）

### 2.1 先行信号矩阵

- 按台账「信号规则」逐条判定；标准矩阵项数由业务配置规定。
- 必须以首期基线矩阵计数为对比锚，按最新数据重算，不得机械沿用。
- 连续 2 期同向才确认；单日 / 单月异常值必须剔除或标注。
- 失真信号必须写明（季节性资金面扰动、单日跳价、集中续约、成交结构变化、单机构重设基线、个别大型项目一次性入市等）。
- 每个信号写：本期读数、方向、信号灯、连续 2 期确认进度、失真剔除说明、对目标市场的含义。

### 2.2 结构红线（比信号灯更严格的硬阈值）

- 红线登记簿阈值取自业务配置与台账「信号规则」表，运行前读取，不得在模板内硬编码。
- **触发动作**：普通红灯允许「触发但待确认」；结构红线一旦触发，必须：启动升级复核、重算情景、暂停新增杠杆类决策建议、不提供买卖价位或仓位建议。
- **归一化方法**：

```
正向指标：当前值 ÷ 红线值 × 100%
反向指标：红线值 ÷ 当前值 × 100%
```

| 归一化距离 | 状态 |
|---|---|
| ≥100% | 触发 |
| 85%–99.9% | 临界 |
| 70%–84.9% | 观察 |
| <70% | 安全 |
| 无数据 | 无法判定 |

- 报告必须同时写：普通红灯数量（矩阵口径 + 信号规则口径）、结构红线触发数 / 临界数、红线阈值为机制自设（非官方）、「红灯 ≠ 红线」的解释。
- 信号规则（K 系）与结构红线（RL 系）的关系：K 系是信号灯（机械阈值）；RL 系是更严格的结构红线。K 触发只作信号灯判定，RL 触发须启动升级复核并重算情景。

### 2.3 传导链

按「宏观变量 → 中间变量 → 资产价格」完整推演，链数下限由业务配置规定（通用建议至少 5 条，覆盖利率 / 供给 / 交付→租赁 / 需求分母 / 外需情绪类）。每条链写：当前读数 / 证据、领先期、已定价程度、尚未定价因素。

### 2.4 已定价 / 未定价 / 反向声音

- 列出 3–5 条「已充分定价」因素；3–5 条「尚未充分定价」因素。
- 至少 1 条反向声音（建议 3 条视角）；反向声音必须标明证据与不确定性，不得为了平衡而编造。

### 2.5 条件化决策框架

只给「条件 → 判断 → 风险提示」；不给具体买卖价位、仓位比例、收益率承诺、买卖时点指令。覆盖的条件组由业务配置定义（至少含：融资再紧、需求确认下行、供给兑现回升、需求分母仍强、红线触发、外部冲击再起）。

### 2.6 升级复核

触发条件（通用默认）：季度内出现任一红灯；口径分歧 >20%；交付兑现率 <45%；许可面积同比 >+30%（业务配置可调整）。触发时必须单列「升级复核」章节：触发清单（阈值 / 本期实际 / 是否触发）、复核结论（维持 / 调整哪些判断）、复核动作与时限、证伪条件。

### 2.7 供给情景重算

- **公式**：`实际交付 = 计划量 × 兑现率`。
- 兑现率至少三档（运行前从台账读取最近已核验值填入；不得在模板内硬编码）。
- 结果按机构分轨，不合并、不取中值；各年分别列示；每个结果标注「区间 / 情景」，不是交付事实。
- 存量增速与人口增速对比时注明跨期、仅量级参考。

## 三、报告结构骨架（11 节固定顺序）

| 节 | 模块 | 核心定位 / 必填内容 |
|---|---|---|
| 1 | 结论先行 | 季度判定、5–6 条核心结论、本期补入 / 缺失的机构、结论矩阵（市场状态、信号矩阵、结构红线、升级复核、外部核验、置信度）。 |
| 2 | 关键数字卡 | 10–13 张；每张标注实际值 / 预测值 / 计划值，及来源、周期、发布日、行内链接。 |
| 3 | 多维全景（含图表） | 按业务配置维度逐维展开，含图表。 |
| 4 | 先行指标传导分析 | 传导链、已定价 / 未定价、反向声音、传导量化（机制自算，标注假设）。 |
| 5 | 信号矩阵与条件化决策框架 | 先行信号矩阵；结构红线登记簿；信号规则逐条判定；条件化决策框架。 |
| 6 | 升级复核 | 触发时单列；未触发时写明「未触发 + 依据」。 |
| 7 | 供给情景重算 | 方法 + 三档兑现率 + 分轨区间。 |
| 8 | 与上期 / 首期基线对比 | 基线偏离、环比 / 同比、偏离度总评与稳健性。 |
| 9 | 数据治理与未核验清单 | 来源分级与核验审计、口径冲突并列、未核验清单、台账指标逐项附录（可展开，行数 = 台账实际项数）、自算口径说明。 |
| 10 | 下季度观察清单 | 带日期与触发条件。 |
| 11 | 页脚（footer 元素，不计入 h2） | 报告路径、指标台账路径、本期新增 / 补入内容。 |

## 四、数据获取协议（业务配置实例化的通用框架）

- 研究总入口 → 最新季度报告页 → PDF 直链与哈希记录（机构 / 报告名 / 统计周期 / 发布日 / 页码 / URL / SHA256）。
- 常驻更新页每周检查；滞后一期只能标「滞后一期」，不得标为当季实际值。
- 发布前未上线：观察清单写「待发布」，不得用媒体转述补数。
- 广域口径与窄域口径不得直接合并。
- 媒体转述只用于发现线索，数值必须回官方页 / PDF 校验。
- 全部机构未取得时：不编造、不用媒体数值冒充官方值；使用最小可替代集（业务配置定义）；结论置信度降为「方向高、幅度中、时点低」；在数据治理章节列出未核验清单与下季度抓取计划。

## 五、渲染要求（季度特化）

- 通用规范第 5 节顶部导航强制；锚点可含子节；标签与节标题逐字一致。
- 图表数量下限由业务配置规定（须含红线归一化距离图与供给情景图）。
- 行内链接式来源承载（通用规范第 4 节 B 式）+ 自定义 hover tooltip（通用规范第 6 节）。
- 指标附录可展开，行数等于台账实际项数；所有表头不含「URL」。

## 七、Agent 执行约定（季度特化）

- 台账 xlsx 默认不改写；报告层补入的机构数据必须在数据治理章节注明「报告层补充，尚未写入当前台账」。
- 若确实需要更新台账，先备份，再新增编号或备注，不得覆盖历史值。
- 不得把「报告层补充」说成「台账已更新」。
