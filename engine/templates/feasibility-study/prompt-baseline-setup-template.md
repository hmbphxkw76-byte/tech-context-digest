# 基线报告类型模板（可行性与市场进入型）

> **用途**：可行性与市场进入型业务线**建立期**的报告类型模板。产出首期可行性论证报告与配套评估框架档案（维度体系、财务测算假设、Go/No-Go 标准），作为后续同类项目论证的对比锚与制度基础。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置（`{地区}/{业务类型}/prompts/business-config.md`）。质量规则见通用基座与通用规范；本文件规定可行性论证型基线报告的差异项与结构骨架；冲突时以业务提示词为准。

---

## 一、基线报告的特殊定位（与后续项目论证的差异）

1. **对比锚属性**：基线报告既是首个项目的论证结论，也是评估框架的制度基础；维度体系、财务测算假设与 Go/No-Go 标准须被后续项目完整继承。
2. **必须收敛到单一决策**：报告必须给出明确的 Go / No-Go / 有条件 Go 建议，不允许「双向平衡不表态」；建议须与完整风险清单并存。
3. **综合集成纪律**：本类型大量引用其他类型报告的结论（行业研究、规模测算、政策解读、竞争情报），引用时注明来源报告与口径，不重复推导。
4. **评估框架档案首建**：运行后建立评估框架档案（评估维度与权重、财务测算假设清单、Go/No-Go 判定标准），回写 `{{REGISTRY_PATH}}`；prompt 模板内严禁填写活值。
5. **产出联动**：基线产出后，`{{BASELINE_REPORT_PATH}}` 即指向本报告；后续项目提示词的该变量值保持不变。

## 二、结论边界（本类型的特别声明）

可行性报告输出**单一项目的 Go/No-Go 论证**，仅对授权决策方负责，不构成对不特定公众的建议；财务测算全部假设可审计；「有条件 Go」须列明条件清单与验证时点；结论与风险清单必须同时呈现。

## 三、报告结构骨架（九节固定顺序）

| 节 | 模块 | 核心定位 / 必填内容 |
|---|---|---|
| 1 | 执行摘要 | 明确建议（Go / No-Go / 有条件 Go，附 3 条核心理由，每条含数据、口径、来源）+ 关键数字卡（投资额、回收期、关键假设）+ 条件清单（如有）。 |
| 2 | 项目范围与评估框架 | 项目定义（目标 / 范围 / 不含项）；评估维度与权重表；Go/No-Go 判定标准（阈值取自业务配置）；评估方法说明。 |
| 3 | 市场可行性 | 市场需求与容量输入（引用来源报告与口径）；目标客群与竞争输入；市场可行性判定（对照判定标准）。 |
| 4 | 技术与运营可行性 | 技术方案要点与依赖；运营资源（团队、渠道、供应链）评估；关键运营假设清单。 |
| 5 | 财务测算 | 假设清单（逐条附依据）；投资额与成本结构；收入测算；回收期 / 内部收益率等指标（多情景：乐观 / 基准 / 悲观）。 |
| 6 | 法规与合规路径 | 适用法规与许可清单（引用政策解读结论，逐条附官方来源）；合规路径与时点；待明确事项。 |
| 7 | 风险与缓解 | 风险登记（逐条：风险 / 触发条件 / 影响量级 / 缓解措施 / 残余风险）；反向声音（高亮块，至少 2 条）。 |
| 8 | 结论与实施路线图 | Go/No-Go 最终建议（对照判定标准逐项打分）；有条件 Go 的条件清单与验证时点；实施路线图（阶段 / 里程碑 / 决策门）。 |
| 9 | 参考来源清单 | 引用的类型报告与一手调研按分级分组，完整 URL / 文件名，逐点可回溯。 |

## 四、框架档案与登记册联动

- 评估维度、判定标准与假设清单由业务配置定义；基线报告须完整呈现「评估维度 × 判定标准 × 结论」追踪表，运行后逐项回写 `{{REGISTRY_PATH}}`。
- 每格活值附 `[来源, 时点]`；未核实项注明「待核实」，不补值、不外推。

## 五、图表与渲染（基线期）

- 交付格式：Markdown 源稿 + 同目录自包含 HTML（经 `engine/tools/md2html.py` 同步生成）。
- HTML 须通过 `engine/tools/lint_reports.py`：表格标签配对为强制项。
- 基线导航采用简化锚点目录，不强制升级为 `.report-nav`。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 九节齐全、顺序正确、编号连续；节标题为该业务线固化锚
- [ ] Go/No-Go 建议明确，逐项对照判定标准打分
- [ ] 财务测算全假设可审计，多情景呈现
- [ ] 引用的其他类型报告来源与口径注明完整
- [ ] 条件清单与验证时点（如有）完整
- [ ] 框架档案与登记册已首建并回写
- [ ] HTML 通过 lint（标签配对）

## 七、维护规范

- **修订触发条件**：结构变更、评估维度调整、判定标准变更、命名规则变更。
- **变更流程**：先改本类型模板 → 同步业务提示词 → 更新版本记录 → 评估该类型全部周期提示词联动。
- **固化保护**：已产出基线报告不得改动；结构变更只影响后续新基线。
