# 年度刷新类型模板（行业深度研究型）

> **用途**：行业深度研究型业务线**运行期**的报告类型模板。每年固定窗口对行业全景做全量刷新，与基线及上年版本对照，完成「口径复核 → 数据刷新 → 格局更新 → 趋势复判」闭环。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；本文件规定年度刷新的差异项与方法框架；冲突时以业务提示词为准。

---

## 一、节拍设计

| 节拍 | 定位 | 触发条件 | 输出 |
|---|---|---|---|
| 年度刷新 | 全量刷新：九节逐节对照更新 | 每年固定窗口 | 完整九节刷新版报告（结构逐字继承基线） |
| 重大事件插刷 | 行业结构性事件（重大并购 / 监管重构 / 技术代际切换）触发对应模块提前刷新 | 业务配置触发器命中 | 刷新版报告提前发布并在变更摘要中说明触发原因 |

- **触发器**清单由业务配置维护（格式：`事件 → 受影响模块`）；命中即刷新，无触发则按年度窗口执行，不得为制造变化而虚构变化。

## 二、更新协议

1. **读取锚**：每次运行必须读取 `{{PREVIOUS_REPORT_PATH}}`（上年版）与 `{{BASELINE_REPORT_PATH}}`，继承九节结构、口径裁决与全部已核实结论。
2. **已修正事实清单**：逐条继承并在产生修正后追加（格式见通用基座第五节），严禁重新引入已被推翻的说法；无来源不得入清单。
3. **边界档案闭环**：运行前从 `{{REGISTRY_PATH}}` 读边界档案（行业边界、产业链口径、玩家清单）→ 复核有效性 → 运行后回写（口径变更留痕、玩家进出登记）。
4. **趋势复判**：上年趋势判断逐条对照实际进展（命中 / 部分命中 / 未命中），复判结论与依据并列呈现；不删除上年判断原文。
5. **产出数据变更摘要**：变更摘要至少覆盖全部研究维度与口径清单，置于报告开头或末章之前。

## 三、各模块更新要点框架

业务提示词按以下框架实例化「要动态获取什么」：

- **产业链**：环节进出、价值分布迁移、传导关系变化。
- **规模与格局**：最新可得口径的规模与增速（多口径并列）、集中度变化、口径修订留痕。
- **玩家**：清单复核（进出与标准）、逐家要点更新（业务、规模、定位，附来源）。
- **驱动与风险**：驱动因素证据更新、新增风险、失效驱动归档。
- **趋势**：上年判断复判 + 新趋势推导（依据 → 推断 → 反向声音）。

## 四、输出与命名（与仓库工具链对齐）

| 节拍 | 文件名（业务目录相对路径） | 版本号 |
|---|---|---|
| 年度刷新 | `reports/{{YYYY}}_annual.md`（+ 同名 html） | 写入报告内（vYYYY.MM.DD） |
| 重大事件插刷 | `reports/{{YYYY-MM-DD}}-主题.md` 追加件 | 同上 |

- 文件命名遵循仓库统一约定（`engine/tools` 按此识别）；插刷追加件命名不在标准正则内，`validate.py` 仅提示 WARN 不阻断，属预期行为。
- 交付格式：md 源稿 + 同目录自包含 HTML（`engine/tools/md2html.py` 同步生成）；HTML 必须通过 `engine/tools/lint_reports.py`（表格标签配对强制）。
- 基线报告常驻 `reports/` 顶层，不进入归档；年度刷新版按归档保留策略执行。

## 五、执行方式（建议）

1. 按研究维度并行启动研究子代理（产业链 / 规模格局 / 玩家 / 驱动风险），全部逐点引用，二手数据须交叉验证。
2. 子代理返回后由主代理读取 `{{PREVIOUS_REPORT_PATH}}` 做差异合并，继承已修正事实清单，应用业务配置的模块更新要点。
3. 冲突口径保留双份引用；无法核实项单列「待复核清单」。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 九节结构与基线逐字一致（顺序、编号不变）
- [ ] 已修正事实清单已继承并续写，无回退
- [ ] 上年趋势逐条复判，原文保留
- [ ] 口径修订留痕；多口径并列不合并
- [ ] 数据变更摘要 + 待复核清单已产出
- [ ] HTML 通过 lint（标签配对）
