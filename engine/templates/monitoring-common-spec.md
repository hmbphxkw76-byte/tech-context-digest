# 监测报告通用规范（渲染 / 排版 / 交付）

> **用途**：本项目所有监测报告共享的 HTML 渲染、表格排版、来源链接、图表与交付规范。各类型模板与本文件冲突时，以类型模板及业务提示词为准；本文件只规定**跨类型、跨业务线一致**的最低渲染标准。
>
> **上位规范**：页面设计系统、结构骨架、可访问性 / 兼容性 / 性能 / 门禁的完整标准见 `engine/docs/page-build-spec.md`（PAGE-BUILD-SPEC v1.0）；本文件是其「报告渲染」细化。冲突时以上位规范为准。

---

## 1. 交付格式与命名规则

- **双格式交付**：每份报告默认 = 同名 `.md` 源 + 自包含 `.html`；业务线可声明**纯 HTML 交付**（md 源稿移 `sources/`，不参与 `md2html` 自动转换，由 `business-config.md` 第一节声明，如 `content/<theme>/<category>/<region>/<业务线>`），纯图表型简报同理。
- **命名规则**：

| 报告类型 | 文件名 | 落盘位置 |
|---|---|---|
| 基线报告 | `{YYYY-MM}_baseline_report.html` | `{业务目录}/reports/` |
| 周报 | `{YYYY-MM-DD}_weekly.html`（日期 = 数据截止日） | 同上 |
| 月度简报 | `{YYYY-MM}_monthly.html` | 同上 |
| 季度报告 | `{YYYY-Qn}_quarterly.html` | 同上 |
| 年度报告 | `{YYYY}_annual.html` | 同上 |

- HTML 必须自包含：全部样式与 JS 内联，ECharts 内联加载，**不依赖外部数据文件**。

---

## 2. ECharts 图表规范（研报风）

- 风格：白底 / 浅底、深色字、无花哨渐变；配色限 navy / red / green / amber。
- 标题必须含**单位与来源**；每个图下有 `chart-note` 说明口径与限制（含统计周期、是否自算）。
- **不得把不同统计域的数值画成一条连续时间序列**；不同口径数值并列或分轴，并注明「不可相减」。
- 图表数量下限由各类型模板与业务配置规定；通用要求每张图可独立核对数据来源。
- 假设性测算图必须标注「假设性测算」并写明全部假设。

---

## 3. 表格结构与列宽

- `<thead>` / `<tbody>` 必须成对且标签完整；禁止畸形写法（如 `<th scope="col"ead>`）与重复 `</tbody>`；每行单元格数与表头列数一致。
- 每个 `<th>` 声明列宽；表格加 `class="fixed"`。两种合法写法：
  - **百分比** `style="width:N%"`（同表头之和 100%）——适用于列宽之和不超过容器、表头可在容器内完整显示的表；
  - **内容适配 px** `style="width:Npx"`，取 `max(既有宽度, 表头文本需求宽)`——适用于宽表（列宽之和 > 容器）。`table-layout:fixed` 会把百分比表锁死在容器宽度，`nowrap` 表头将文字溢出；px 之和超过容器时表格自动撑开，由 `.tblwrap{overflow-x:auto}` 横向滚动。
  - 判定：先按百分比排；若任一列的百分比宽度小于其表头文本需求宽，则整表改用内容适配 px。
- **禁止列宽塌缩**：末列不得被压成竖排文字（中文逐字换行）。多列表（≥7 列）为高风险表，须逐表校验。
- 表格内**不设独立「完整 URL」列**；来源链接按第 4 节承载。

---

## 4. 来源链接呈现

两种承载方式，同一报告可混用，但同一张表只用一种：

**A. 表头弹层式**：来源清单类表格，表头加 `class="src-head" tabindex="0"`，悬停 / 聚焦展开 `.src-pop` 弹层，集中列出本期全部来源链接（每条 `target="_blank" rel="noopener"`，链接文本为机构 / 文件名）。

**B. 行内链接式**：数据表的「指标名称」或「机构名称」本身即链接：`href` 写完整 URL，链接文字保持指标名 / 机构名原样（不把 URL 当链接文本），文字后加 `↗`；多来源行在每个机构上分别加链接。

通用要求：

- 全部链接 `target="_blank"` + `rel="noopener"`。
- 行内引用 `[Source: 完整URL, 年份]` 保持完整可访问。
- URL 必须写入来源清单、台账或数据底表，报告中不得出现「断头数字」（有数无源）。
- 链接样式（行内式）：navy 色、虚线下划线、末尾 `↗`、hover 背景浅蓝。

---

## 5. 固定顶部导航与锚点

- 全部报告统一采用 **canonical 结构**：`<header class="report-head">`（早期业务线可用同义类 `.hero`）
  + `<nav class="report-nav" aria-label="报告导航">`（置于 `<header>` 之后、`<main>` 之前）
  + `<main class="wrap">`；页头 / 导航 / 章节 / 表格等样式由 `engine/tools/report_style.py`
  的 `CANONICAL_CSS` 统一提供（HTML 逐份内联，满足自包含要求）。
  - `.nav-url`：标签「报告 URL」+ 本报告仓库原始文件完整链接（`{{REPO_RAW_URL_BASE}}` + 业务目录相对路径，基址由业务配置定义）；周期报告（月 / 季 / 年）强制。
  - `.nav-tabs`：锚点标签与报告章节一一对应；标签文案与章节标题一致；`href="#sN"` 与对应 `<h2 class="sec" id="sN">` 逐字对应。
  - 样式与交互：sticky 常驻、平滑滚动、`scroll-margin-top:100px`、窄屏换行。
- 迁移既有报告用 `python engine/tools/restyle_reports.py --files <报告.html>`；md 源转 HTML 用 `md2html.py`（同样输出 canonical 结构）。
- **基线特例**：基线报告（含机制建立文档、首次覆盖、一次性深度件）允许使用简化锚点目录（`<nav>` 不含 `.report-nav` / `.nav-url` 组件），不强制 canonical 顶部导航；自首个周期报告（月 / 季 / 年 / 周）起强制 canonical 结构。

---

## 6. 自定义 hover URL 提示（使用行内链接式的报告）

- 不使用浏览器原生 `title`；使用自定义 tooltip：`position: fixed`、深色背景白色文字、最大宽度 560px、`word-break: break-all`、跟随鼠标、自动避开视口边缘、鼠标移出 / 滚动 / 缩放时隐藏、键盘聚焦链接时也显示。
- 提示内容为链接的完整 `href`；交互脚本放在独立 IIFE 中，ECharts 加载失败时仍可运行。

---

## 7. 响应式与打印

- 最大宽度约 1160px；移动端表格横向滚动；移动端图表高度 320px。
- 打印时保留表格边框与来源备注，不依赖 hover。

---

## 8. 可访问性与校验

- 内联 JS 必须通过 `node --check`；表格 / div 标签配对；锚点有效；浏览器打开预览无控制台 error。
- HTML 可访问性校验：`python engine/tools/lint_reports.py`（按可用性执行；本地环境缺脚本时以人工清单替代，见第 9 节）。

---

## 9. 人工校验清单（脚本缺失时的回归替代）

- [ ] 所有锚点跳转准确；导航标签与章节标题逐字一致
- [ ] 所有表格 `<thead>` / `<tbody>` 成对、列宽声明、无竖排塌缩
- [ ] 来源链接可点击访问；弹层链接数与来源条目一致
- [ ] 图注含单位、来源、统计周期、口径警示
- [ ] 浏览器打开无控制台 error
- [ ] 分层交付 / 信息等级 / 新增信息统计模块齐全（第十节）

---

## 10. 信息分层与密度（强制，新报告 `[E]`）

- **三层交付**：决策摘要（≤1 屏，仅结论）/ 证据层（逻辑）/ 原始层（台账与来源）；共享 boilerplate（来源分级规则、口径声明模板、研究局限模板）上移至[通用基座](prompt-generic-base.md)第十节与[信息分层规范](information-layering-spec.md)，报告正文只写专属口径与前提假设。
- **信息等级四级**：关键信息标注 `已核验 / 部分核验 / 推断 / 假设`（`class="lvl lvl-*"`）；决策摘要仅允许已核验 + 部分核验；market-sizing 数值必须标「假设乘积」。
- **新增信息统计模块**：报告开头输出「本期新增 X 条 / 修正 Y 条 / 无变化 Z 条 / 假设核验进度 k/n」。
- **指针引用**：事实唯一定义于台账 / 登记册 / 事实卡片（`[FC-…]`），正文用「指标编号 + 指针」引用，删除同义复述。
- 完整规则见[信息分层规范](information-layering-spec.md)与[决策交付规范](decision-delivery-spec.md)；门禁为 `info_density_check.py` / `fact_card_check.py`。
