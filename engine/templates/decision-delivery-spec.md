# 决策交付规范（DECISION-DELIVERY-SPEC v1.0）

> **用途**：本项目所有报告与决策仪表盘的**决策支撑**规范，目标把信息高效转化为可落地决策。与[信息分层规范](./information-layering-spec.md)、[通用基座](./prompt-generic-base.md)配套。
>
> **适用**：全部业务线报告；跨研究线决策层（`content/economy/insight`）为强制载体。
>
> **单一事实源纪律**：决策卡 / 行动协议 / 盲区消号 / 版本治理的唯一规范来源；业务配置只实例化。

---

## 一、决策卡（标准化结构）

每条研究线对每个核心判断输出一张决策卡，字段固定：

| 字段 | 说明 |
|---|---|
| `conclusion` | 结论（一句话，含信息等级） |
| `evidence_strength` | 证据强度：强 / 中 / 弱（按已核验事实占比与双源覆盖） |
| `trigger` | 触发条件（可观测、带阈值） |
| `counter_evidence` | 反向证据（至少 1 条；无则写「未发现」并说明检索范围） |
| `sufficiency` | 信息充分度：**可直接决策** / **需补充 X 类信息才可决策** |

- 决策卡汇编成跨研究线**决策仪表盘**（见第三节）。
- 证据强度规则：强 = 关键事实全部已核验且双源；中 = 主体已核验、个别部分核验；弱 = 含推断/假设支撑。

## 二、行动协议化（触发条件 + 阈值 + 责任角色 + 时限 + 验证指标）

### 2.1 标准化结构

报告中的「可执行启示 / 行动建议」一律改写为：

```
[优先级] 行动：<动作>
  触发条件：<可观测事件>
  阈值：<数值 / 区间>
  责任角色：<研究负责人 / 数据采集 / 模型负责人 / CI>
  时限：<YYYY-MM-DD 或 T+N 日>
  可观测验证指标：<指标编号 + 期望方向>
```

### 2.2 优先级三档

| 档位 | 定义 | 示例 |
|---|---|---|
| **立即行动** | 触发条件已满足或阈值已突破，须在本期处理 | 硬红线触发、来源发布后 30 日内入库 |
| **持续观察** | 未触发但接近阈值，纳入监测日历 | 距硬红线 ≤25bp、连续 2 期确认 |
| **仅记录存档** | 信息不足或影响不明确，只登记不行动 | 三级信号灯触发、单源转述 |

### 2.3 规则

- 缺少任一要素（触发条件 / 阈值 / 责任角色 / 时限 / 验证指标）的行动项 = `[E]`（新报告）。
- 行动项不得给出买卖价位 / 杠杆 / 仓位建议（通用基座结论边界）。

## 三、决策仪表盘（跨研究线统一决策层）

### 3.1 架构（参照 jp-life-work `00-decision-hub`）

- 载体：业务线 `content/economy/insight`，类型 `decision-dashboard`。
- 三功能：
  1. **收敛**：各研究线结论 → 标准化决策卡（结论 / 证据强度 / 触发条件 / 反向证据 / 信息充分度）。
  2. **暴露**：标记缺失事实与冲突读数（信息充分度不足项）。
  3. **触发**：按缺失清单与阈值启动补缺 / 专题任务。
- 决策卡台账：`data/processed/economy/insight/decision_cards.json`；场景切片：`data/processed/economy/insight/scenario_slices.md`。

### 3.2 决策仪表盘报告骨架（decision-dashboard 基线）

1. 决策摘要（跨线 Top 结论 + 信息充分度分布）
2. 决策卡总表（按研究线）
3. 证据强度与反向证据
4. 触发条件与阈值距离
5. 信息充分度与缺失清单
6. 行动协议（三档）
7. 场景切片（投资 / 就业 / 政策）
8. 盲区与消号进度
9. 参考来源与读数时点

## 四、核心决策模型输出契约（禁止留白）

`transmission.py`（弹性 + 时滞）、`policy_multiplier.py`（乘数）、`valuation.py`（cap rate / DCF）、`stress_test.py`（尾部压力）为决策支撑的核心模型。契约：

1. **即使参数未核验，也必须输出参数区间与对应假设**；禁止模块留白或返回空结果。
2. 输出必须含：参数区间（低 / 中 / 高）、假设清单（编号 + 内容 + 等级）、时滞、置信区间、来源。
3. 未核验参数标「经验估计 / 假设乘积」，不得作为确定点值进入决策摘要。
4. 模型失败须显式上报（退出码 1/2），不得静默降级。

## 五、阈值校准与 ex-ante 标注

- **首次回测时间点：2027-06**（中期回测，提前于原计划 2027-12）；2027-12 全期回测。
- 校准对象：全部登记指标（编号见业务配置 / 台账）；输出置信区间（95% CI）与分位依据。
- **校准完成前（当前至 2027-06），所有信号灯必须标注「预校准（ex-ante）」**；未标注 = `[E]`（新报告）。
- 工具：`threshold_calibration.py`；状态计数替代触发计数；历史阈值与变更留痕，不得事后改写。

## 六、盲区变量消号机制

- 台账：`engine/report-audits/blind-spot-ledger.md`；字段：ID / 项目 / 优先级 / 影响 / 发现日期 / 责任周期 / 消号条件 / 状态 / 关联 KPI。
- **P0 优先级类别**（优先补充）由业务配置定义；其余为 P1/P2。
- 消号条件（任一）：①官方一手 + 双源确认；②确认永远无官方序列并以高频代理替代（记录代理与校准）；③证明对结论无实质影响（敏感性证明）。
- 闭环：每月复盘会审；季度报告公布状态；未消号项须更新责任周期。
- 校验：`blind_spot_check.py`（字段完整 / P0 类别存在 / 责任周期有效 / 状态合法）。

---

## 七、版本噪声治理

- **核验类、收敛型运行不新增独立版本号**；统一合并标注为「**本期读数时点 YYYY-MM-DD**」。
- **周期报告版本号口径**：周期报告内 `{{REPORT_VERSION}}`（vYYYY.MM.DD）为**读数时点标识**，不等同语义版本升级；仅核心事实修正升级语义版本号（vN → vN+1）。
- 仅当发生**核心事实修正**时才升级版本号（vN → vN+1），并在「已修正事实清单」留痕。
- 报告头部须同时显示：`报告版本 vN` + `本期读数时点`；核验 / 收敛型报告以读数时点为主标识。
- 禁止 v1–v5 式无意义频繁刷新历史；历史版本保留不删，但不因规范刷新而改版本号。
