# 周期更新类型模板（职业就业调研型）

> **用途**：职业就业调研型业务线**运行期**的报告类型模板，覆盖月度（核验轻运行）/ 季度（主更新节拍）/ 年度（复盘）三档节拍。以 `{{SOURCE_LANGUAGE_RULE}}` 指定语言的一手与权威来源为依据、以上一期报告与首期基线为对比锚，完成「核验 → 更新 → 建议 → 可靠性」闭环。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；本文件规定职业就业调研型周期更新的差异项与方法框架；冲突时以业务提示词为准。

---

## 一、节拍设计（三档）

| 节拍 | 定位 | 触发条件 | 输出 |
|---|---|---|---|
| 月度 | 核验型轻运行：只核验登记册活值与触发器状态，不重写报告 | 常规月度窗口；**无触发不启动新报告**，仅在登记册标注「截至本次日期无更新」 | 登记册更新记录；命中触发器时升级为季度重点更新 |
| 季度 | 主更新节拍：全模块刷新 | 每季度窗口，或任一重大事件触发器命中 | 完整九节更新版报告（结构逐字继承基线） |
| 年度 | 复盘：预测对照 + 清单复审 + 路线图重排 | 每年固定窗口 | 年度版报告 + 登记册年度新版（另存，不覆盖历史） |

- **重大事件触发器**清单由业务配置维护（格式：`事件 → 受影响模块`）；命中任一触发器即触发对应模块重点更新；无触发则降级为核验 / 收敛型轻运行，不得为制造变化而虚构变化。
- 与上期同日或仅隔 1 日时，明确写「本期为 T+1 刷新，官方发布窗口未开，价值在于核验、口径澄清」。

## 二、更新协议

1. **读取锚**：每次运行必须读取 `{{PREVIOUS_REPORT_PATH}}` 与 `{{BASELINE_REPORT_PATH}}`，继承九节结构、口径裁决与全部已核实结论。
2. **已修正事实清单**：逐条继承并在产生修正后追加（格式见通用基座第五节），严禁重新引入已被推翻的说法；无来源不得入清单。
3. **登记册闭环**：运行前从 `{{REGISTRY_PATH}}` 读活值 → 核验 → 运行后回写；每期逐项填写「是否更新」，未变动项注明「截至 {{CURRENT_DATE}} 无更新」。
4. **薪资等核心指标交叉验证**：按业务配置来源优先级抓取至少 N 家独立来源（N 由业务配置规定）；冲突并列呈现，不静默择一。
5. **产出数据变更摘要与待复核清单**：变更摘要至少覆盖登记册全部追踪项，置于报告开头或末章之前。

## 三、各模块更新要点框架

业务提示词按以下框架实例化「要动态获取什么」：

- **市场与政策**：国家 / 城市层面与监测主题（`{{TOPIC}}`）相关的战略实施进展、新法规生效、国际指数排名、权威机构支出与规模预测更新（多口径并列）。
- **人才供需与薪酬**（最高优先级）：权威人力研究新版、人才池数据、最难填补岗位与周期；薪酬指南最新年版分表；招聘平台抽样；保持「岗位 × 职级」交叉分层表与计价单位、净薪 / 总包模型。
- **雇主生态**：重点实体动态、人数、收购、合作、国家级新计划；标注任何未能核实的实体并给复核入口。
- **岗位技能**：在招岗位抽样（样本量声明）、专项技能框架版本更新、工具栈与语言要求变化。
- **资质证书**：新证发布、考试费与前置条件、本地考点日程、监管内嵌证书要求变化。
- **落地路径**：签证门槛与流程变化、招聘机构评级复核、实操清单条目复核。

## 四、输出与命名（与仓库工具链对齐）

| 节拍 | 文件名（业务目录相对路径） | 版本号 |
|---|---|---|
| 月度 | `reports/{{YYYY-MM}}_monthly.md`（+ 同名 html） | 写入报告内（vYYYY.MM.DD） |
| 季度 | `reports/{{YYYY-Qn}}_quarterly.md`（+ 同名 html） | 同上 |
| 年度 | `reports/{{YYYY}}_annual.md`（+ 同名 html）+ 登记册年度新版 | 同上 |

- 文件命名遵循仓库统一约定（`engine/tools` 按此识别）；业务线如需保留旧版本文号，写入报告文首/文末标注，不进入文件名。
- 交付格式：md 源稿 + 同目录自包含 HTML（`engine/tools/md2html.py` 同步生成）；HTML 必须通过 `engine/tools/lint_reports.py`（表格标签配对强制）。
- 基线报告常驻 `reports/` 顶层，不进入归档；周期报告按归档保留策略执行。

## 五、执行方式（建议）

1. 按调研维度启动并行研究子代理（市场政策 / 薪酬供需 / 技能证书 / 落地路径），全部限定业务配置声明的来源语言、逐点引用。
2. 子代理返回后由主代理读取 `{{PREVIOUS_REPORT_PATH}}` 做差异合并，继承已修正事实清单，应用业务配置的模块更新要点。
3. 冲突数据保留双份引用；无法核实项单列「待复核清单」。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 九节结构与基线逐字一致（顺序、编号不变）
- [ ] 已修正事实清单已继承并续写，无回退
- [ ] 追踪表逐项核对并回写登记册；prompt 模板无硬编码活值
- [ ] 薪酬交叉分层表、净薪 / 总包模型等核心框架保留
- [ ] 来源语言规则执行结果已声明；零违规来源
- [ ] 数据变更摘要 + 待复核清单已产出
- [ ] HTML 通过 lint（标签配对）
