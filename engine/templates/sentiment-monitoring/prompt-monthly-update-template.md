# 周期更新类型模板（舆情传播监测型）

> **用途**：舆情传播监测型业务线**运行期**的报告类型模板，覆盖月度（舆情月报节拍）与事件触发（风险预警升级）两档。以上一期报告与首期基线为对比锚，完成「抓取 → 判定 → 对比 → 预警」闭环。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；本文件规定舆情传播监测型周期更新的差异项与方法框架；冲突时以业务提示词为准。

---

## 一、节拍设计（两档）

| 节拍 | 定位 | 触发条件 | 输出 |
|---|---|---|---|
| 月度 | 舆情月报：声量与情感全量刷新 | 常规月度窗口 | 完整九节更新版报告（结构逐字继承基线） |
| 事件触发 | 预警升级：命中信号规则时对应模块重点刷新 | 任一预警阈值命中 | 月度报告外追加专项预警；未命中时在登记册标注「截至本次日期无更新」 |

- **预警触发器**清单由业务配置维护（格式：`信号命中 → 受影响模块`）；命中即触发对应模块重点更新；无触发则不得为制造变化而虚构变化。
- 突发负面热点须当期核实（确认非机器人 / 断章取义）并升级，不等待月度窗口。

## 二、更新协议

1. **读取锚**：每次运行必须读取 `{{PREVIOUS_REPORT_PATH}}` 与 `{{BASELINE_REPORT_PATH}}`，继承九节结构、口径裁决与全部已核实结论。
2. **已修正事实清单**：逐条继承并在产生修正后追加（格式见通用基座第五节），严禁重新引入已被推翻的说法；无来源不得入清单。
3. **台账闭环**：运行前从 `{{REGISTRY_PATH}}` 读议题与渠道活值 → 抓取核验 → 运行后回写；每期逐项填写「是否更新」，未变动项注明「截至 {{CURRENT_DATE}} 无更新」。
4. **环比口径一致**：声量与情感读数须与基线期同渠道、同关键词组、同口径对比；口径变更须在报告中显式标注并保留新旧口径对照。
5. **产出舆情变更摘要**：变更摘要至少覆盖全部监测议题（声量 / 情感 / 预警状态），置于报告开头或末章之前。

## 三、各模块更新要点框架

业务提示词按以下框架实例化「要动态获取什么」：

- **舆论场结构**：渠道声量结构变化、新渠道出现、关键参与方变动。
- **议题声量**：议题声量环比 / 同比、新议题登记、旧议题降温归档。
- **情感判定**：情感分布变化、判定规则命中情况、人工复核抽样结果。
- **风险预警**：信号规则命中状态、热点事件榜、意见领袖观点摘编（附原文链接）、与量化指标的交叉验证结论。

## 四、输出与命名（与仓库工具链对齐）

| 节拍 | 文件名（业务目录相对路径） | 版本号 |
|---|---|---|
| 月度 | `reports/{{YYYY-MM}}_monthly.md`（+ 同名 html） | 写入报告内（vYYYY.MM.DD） |
| 事件触发 | 月度报告内专项章节或 `reports/{{YYYY-MM-DD}}-主题.md` 追加件 | 同上 |

- 文件命名遵循仓库统一约定（`engine/tools` 按此识别）；事件触发追加件命名不在标准正则内，`validate.py` 仅提示 WARN 不阻断，属预期行为。
- 交付格式：md 源稿 + 同目录自包含 HTML（`engine/tools/md2html.py` 同步生成）；HTML 必须通过 `engine/tools/lint_reports.py`（表格标签配对强制）。
- 基线报告常驻 `reports/` 顶层，不进入归档；周期报告按归档保留策略执行。

## 五、执行方式（建议）

1. 按渠道并行启动抓取与判定子代理，全部限定公开来源、逐点附抓取时间与 URL。
2. 子代理返回后由主代理读取 `{{PREVIOUS_REPORT_PATH}}` 做差异合并，继承已修正事实清单，应用业务配置的模块更新要点。
3. 情感判定结果抽样人工复核（比例由业务配置规定）；无法核实项单列「待复核清单」。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 九节结构与基线逐字一致（顺序、编号不变）
- [ ] 已修正事实清单已继承并续写，无回退
- [ ] 台账逐项核对并回写登记册；prompt 模板无硬编码活值
- [ ] 环比口径一致或新旧口径对照已标注
- [ ] 舆情变更摘要 + 待复核清单已产出
- [ ] HTML 通过 lint（标签配对）
