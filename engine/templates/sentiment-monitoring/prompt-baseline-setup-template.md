# 基线报告类型模板（舆情传播监测型）

> **用途**：舆情传播监测型业务线**建立期**的报告类型模板。产出首期舆论场基线报告与配套议题声量台账，作为后续所有周期更新的对比锚与制度基础。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置（`{地区}/{业务类型}/prompts/business-config.md`）。质量规则见通用基座与通用规范；本文件规定舆情传播监测型基线报告的差异项与结构骨架；冲突时以业务提示词为准。

---

## 一、基线报告的特殊定位（与周期更新的差异）

1. **对比锚属性**：基线报告是后续所有周期更新的对比锚；渠道清单、关键词与议题体系、情感判定规则须被后续更新完整继承。
2. **无上期报告**：不读取 `{{PREVIOUS_REPORT_PATH}}`；「已修正事实清单」为空，产生修正后逐条补记（格式见通用基座第五节）。
3. **台账首建**：运行后建立舆情台账（渠道清单、关键词 / 议题登记、基线声量读数、情感判定规则、触发器），回写 `{{REGISTRY_PATH}}`；prompt 模板内严禁填写活值。
4. **言论≠事实声明**：舆情数据是公开言论而非市场事实；报告中须固定声明「舆情热度不等于市场真实状况」，重大结论须与量化指标交叉验证（如业务线同时运行市场指标监测型）。
5. **产出联动**：基线产出后，`{{BASELINE_REPORT_PATH}}` 即指向本报告；后续周期提示词的该变量值保持不变。

## 二、结论边界（本类型的特别声明）

舆情报告输出**舆论态势与风险预警**，不输出「公众必然如何反应」的断言；情感判定为工具辅助 + 人工复核的混合结果，须声明方法与误差边界；不基于舆情给出投资或决策建议。

## 三、报告结构骨架（九节固定顺序）

| 节 | 模块 | 核心定位 / 必填内容 |
|---|---|---|
| 1 | 执行摘要 | 核心判断（编号条目，每条含数据、口径、来源）+ 声量与情感一句话态势 + 风险预警综述 + 来源与时点。 |
| 2 | 监测机制设计 | 数据流（渠道层 → 议题层 → 信号层 → 输出层）；监测节拍（月度月报 + 事件触发预警）；渠道清单与覆盖声明。 |
| 3 | 舆论场结构首描 | 渠道声量结构表（渠道 / 声量占比 / 口径 / 来源）；关键参与方识别（媒体 / 意见领袖 / 普通用户分层）。 |
| 4 | 议题与基线声量 | 议题登记（编号 + 议题 + 关键词组 + 基线声量 + 口径 + 来源）；基线期情感分布（正 / 中 / 负 + 判定方法）。只呈现读数，不做预警判定。 |
| 5 | 情感与热度信号规则 | 信号规则表（编号：监测对象 / 预警阈值 / 确认标准 / 动作）；阈值由业务配置定义；反向声音（高亮块，至少 2 条）。 |
| 6 | 来源与研判治理 | 来源分级表；情感判定方法声明（工具 + 人工复核比例）；首期核验审计（未核验项：项目 / 状态 / 处置）。 |
| 7 | 风险与盲区 | 渠道覆盖缺口、样本偏差（ vocal minority 问题）、机器人与水军干扰；时效与口径局限。 |
| 8 | 交付物与后续运行方式 | 交付物表；月度与事件触发的运行方式。 |
| 9 | 参考来源清单 | 按来源分级分组，完整 URL，逐点可回溯。 |

## 四、台账与登记册联动

- 渠道与议题清单由业务配置定义；基线报告须完整呈现「监测议题 × 优先渠道」追踪表，运行后逐项回写 `{{REGISTRY_PATH}}`。
- 每格活值附 `[来源, 抓取日期]`；未核实项注明「待核实」，不补值、不外推。

## 五、图表与渲染（基线期）

- 交付格式：Markdown 源稿 + 同目录自包含 HTML（经 `engine/tools/md2html.py` 同步生成）。
- HTML 须通过 `engine/tools/lint_reports.py`：表格标签配对为强制项。
- 基线导航采用简化锚点目录，不强制升级为 `.report-nav`。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 九节齐全、顺序正确、编号连续；节标题为该业务线固化锚
- [ ] 全部监测议题 covered，基线声量读数齐全且附口径
- [ ] 言论≠事实声明与交叉验证说明已写入
- [ ] 情感判定方法与误差边界已声明
- [ ] 台账已首建并回写；prompt 模板无硬编码活值
- [ ] HTML 通过 lint（标签配对）

## 七、维护规范

- **修订触发条件**：结构变更、渠道 / 议题调整、信号规则变更、判定方法变更、命名规则变更。
- **变更流程**：先改本类型模板 → 同步业务提示词 → 更新版本记录 → 评估该类型全部周期提示词联动。
- **固化保护**：已产出基线报告不得改动；结构变更只影响后续新基线。
