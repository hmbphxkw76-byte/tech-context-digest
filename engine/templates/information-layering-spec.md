# 报告信息分层与密度规范（INFORMATION-LAYERING-SPEC v1.0）

> **用途**：本项目所有报告共享的**信息结构与密度**规范，目标是提高有效信息密度、系统性降低冗余。与[通用基座](./prompt-generic-base.md)、[监测报告通用规范](./monitoring-common-spec.md)、[决策交付规范](./decision-delivery-spec.md)配套；冲突时以通用基座「结论边界」与来源语言规则为最高约束。
>
> **适用**：全部业务线报告（基线 / 月 / 季 / 年 / 周报）与决策仪表盘。历史报告按门禁周期降级为 `[W]`，不追溯阻断。
>
> **单一事实源纪律**：本文件是「信息分层 / 信息等级 / 新增信息量化 / 事实卡片 / 场景切片」的唯一规范来源；业务配置只实例化，不复述规则正文。

---

## 一、分层交付架构（决策摘要 / 证据层 / 原始层）

### 1.1 三层定义与功能边界

| 层 | 载体 | 功能 | 允许内容 | 禁止内容 |
|---|---|---|---|---|
| **决策摘要** | 报告开头独立节（标题含「决策摘要」或类型模板的「执行摘要 / 结论先行」） | **仅输出结论**：本期判定 + 关键变化 + 决策含义 | 已核验事实、部分核验信息；结论性判断 | 模型参数、口径细节、来源全文、假设点值 |
| **证据层** | 报告正文各节 | **负责逻辑解释**：传导机制、弹性/时滞、口径裁决、假设与不确定性 | 推断、假设、自算、参数区间、反向证据 | 与决策摘要逐字复述的结论 |
| **原始层** | 来源清单、指标台账、数据底表、模型输出（JSON/CSV）、事实卡片库 | **机器可读的结构化数据与可追溯证据** | 指标编号、来源 URL、核验状态、原始数值 | 面向读者的结论性文字 |

### 1.2 决策摘要硬约束

- **长度 ≤ 1 屏**：桌面端不超过约 900 个中文字符或 12 个要点（取更严）；移动端不强制像素计算，但不得长于正文首个证据节。
- **仅允许引用「已核验事实 + 部分核验」等级的信息**（见第二节）；「推断 / 假设」不得作为决策摘要中的结论性数值。
- **market-sizing 类数值**（TAM/SAM/SOM、规模预测、情景测算）必须标注为「**假设乘积**」，**禁止作为确定点值**进入决策摘要；只允许以「区间 + 假设编号」形式出现。
- 决策摘要与正文**不得同义复述**：摘要给结论，正文给逻辑；同一判断只在摘要出现一次，正文以「见决策摘要」指针引用。

### 1.3 共享 boilerplate 上移（消除重复编码）

以下固定通用板块**统一上移至共享层**，单份报告正文只保留该报告专属的特殊口径与前提假设：

| 板块 | 上移载体 | 报告正文处理 |
|---|---|---|
| 来源分级规则（四层定义与采信规则） | 通用基座第四节 | 以指针引用，不复制规则正文 |
| 口径声明模板（实际/预测/计划/自算/假设） | 通用基座第三节 + 本规范附录 A | 仅写本报告专属口径 |
| 研究局限模板（样本、覆盖、时效、访问限制） | 本规范附录 B | 仅写本报告特有限制 |
| 信息等级标注规则 | 本规范第二节 | 仅写本报告出现的等级分布 |
| 版本与读数时点规则 | [决策交付规范](./decision-delivery-spec.md) 第七节 | 仅写本期读数时点与版本处理 |

> **目标**：单份报告减少 20–30% 的重复编码工作量；新增报告默认不再复制上述板块正文。

## 二、信息等级标注（四级）与引用约束

### 2.1 四级定义

| 等级 | 标记 | 定义 | 典型来源 |
|---|---|---|---|
| **已核验事实** | `已核验` | 官方一手或行业机构 PDF，双源方向一致，含 URL / 日期 / 页码 | 央行、统计局、主管部门、国际组织、机构官方报告 |
| **部分核验** | `部分核验` | 单源已核验，或双源存在口径差异但方向一致；或滞后一期官方值 | 单一官方页、机构季报、滞后值 |
| **推断** | `推断` | 基于已核验事实的机制分析、模型推演、弹性外推 | 传导链、情景分析、回归结果 |
| **假设** | `假设` | 未经核验的参数、假设乘积、经验区间 | 兑现率档位、弹性经验值、market-sizing 参数 |

### 2.2 标注方式

- **行内标记**：关键信息后加 `<span class="lvl lvl-verified">已核验</span>` / `lvl-partial` / `lvl-inferred` / `lvl-assumption`（canonical 样式见 `engine/tools/report_style.py`）。
- **表格**：设「等级」列，或表头注明全表等级。
- **决策摘要**：每个结论性要点末尾标注等级；未标注视为不合规。

### 2.3 引用约束（硬规则）

1. 决策摘要**仅允许**「已核验事实 + 部分核验」；出现「推断 / 假设」= `[E]` 阻断（新报告）。
2. 所有 market-sizing 数值必须标「**假设乘积**」；未标注 = `[E]`。
3. 假设进入信号合成或决策摘要点值 = `[E]`。
4. 信息等级标注缺失的关键信息 = `[W]`（历史报告）/ `[E]`（新报告，按门禁周期）。

## 三、单一事实源 + 指针机制

### 3.1 原则

- **所有事实仅在统一台账 / 登记册中唯一一次定义**；报告正文以「**指标编号 + 指针**」引用，不复制定义。
- 指标编号体系（业务配置定义，如 `K01`、`P*`、`S*`、`M*`、`G*`）保持稳定；新增指标须先登记台账/字典。
- **事实卡片**（跨报告共享底座）以 `FC-<域>-<序号>` 引用，见第五节。

### 3.2 Top5 摘要 / 正文 / 看板 边界

| 载体 | 功能 | 输出 |
|---|---|---|
| Top5 / 决策摘要 | 结论 | 不超过 5 条结论 + 等级标注 |
| 正文 | 逻辑 | 机制、弹性/时滞、口径、假设、反向证据 |
| 数据看板 / 台账 | 机器可读 | 指标编号、数值、单位、来源 ID、核验状态、读数时点 |

- **全面删除同义复述**：同一数值 / 结论在三类载体中只出现一次（摘要结论、正文逻辑、看板数值各司其职，不互相复制）。
- 看板数值与台账不一致 = `[E]`（数值一致率指标，见 `metrics-dictionary.json` A-03）。

## 四、新增信息量化模块（必填模板）

### 4.1 模板

每期报告开头（决策摘要之前或之后）必须输出标准化统计模块：

```
本期新增信息 <X> 条 ｜ 修正 <Y> 条 ｜ 无变化 <Z> 条 ｜ 假设核验进度 <k>/<n>
```

- **新增**：本期相对上期首次入库且进入报告的实质信息（事实或结论）。
- **修正**：对上期/基线已核实结论的更正（与「已修正事实清单」对应）。
- **无变化**：核对后维持原判的追踪项数。
- **假设核验进度**：本报告涉及的关键假设中，已核验 / 部分核验 / 推断 / 假设 的数量比 `k/n`（k = 已核验 + 部分核验数，n = 关键假设总数）。

### 4.2 呈现

- 用 `.delta-strip` 四项统计条（canonical 组件）或等价表格；数值为整数，`k/n` 为分数。
- 核验 / 收敛型运行（无新发布）允许 `X=0`，但必须显式写出「本期无新增，读数时点 …」。
- 首期为空时写「基线首期：新增 = 全部基线项」，不得留白。

### 4.3 校验

`info_density_check.py` 检查模块存在与四项字段完整；缺失 = `[E]`（新报告）。

## 五、跨报告事实卡片层（去重底座）

### 5.1 适用范围

`security`（AI 网安就业）、`industry-research`（AI 网安行业深度）、`competitive-intelligence`（竞争情报）三类报告共享同一事实底座，必须复用统一**事实卡片**，避免多份报告内容同质化。

### 5.2 卡片协议

卡片库位于 `engine/fact_cards/`（每域一 JSON + README）。字段：

| 字段 | 说明 |
|---|---|
| `card_id` | `FC-<域>-<三位序号>`，全域唯一 |
| `fact` | 事实陈述（唯一一次定义） |
| `source` | 来源机构 + URL + 发布/核验日期 |
| `tier` | 1 官方一手 / 2 行业机构 / 3 挂牌门户 / 4 媒体转述 |
| `verify_status` | 已核验 / 部分核验 / 未核验 |
| `level` | 已核验事实 / 部分核验 / 推断 / 假设 |
| `updated` | 最近更新日期与更新内容摘要 |
| `indicators` | 关联指标编号（指针） |

### 5.3 使用规则

1. 报告正文引用卡片：`[FC-SEC-001]`，**不得复制卡片全文**；复述仅限于结论性一句话并标注等级。
2. 新增事实必须先登记卡片（或明确标注「新增卡片待登记」），再进入报告。
3. 同一卡片被多份报告引用时，更新内容只维护在卡片库，报告侧以「更新内容」指针同步。
4. 卡片库变更须记录来源与更新内容；禁止无来源新增。

### 5.4 校验

`fact_card_check.py`：卡片 JSON 结构完整；报告内 `[FC-…]` 引用可解析且卡片存在；新增卡片字段齐全。

## 六、读者场景切片

### 6.1 三类场景

| 场景 | 决策问题 | 切片内容 |
|---|---|---|
| **投资决策** | 值不值得进 / 投 / 持 | 估值区间、收益安全垫、触发条件、尾部损失 |
| **就业决策** | 能不能去 / 怎么去 | 供需缺口、薪酬区间、技能要求、路径与时限 |
| **政策制定** | 政策含义与合规应对 | 政策台账、乘数区间、影响对象矩阵、时间线 |

### 6.2 规则

- 每条业务线在业务配置声明其**主场景**与**次场景**；报告产出对应切片（报告内独立节或独立切片页）。
- **取消单份报告服务所有受众**：切片只输出该场景所需信息，不重复全量正文。
- 切片须标注信息等级与读数时点；跨切片共享事实走事实卡片 / 台账指针。

## 七、校验规则汇总（info_density_check.py）

| 规则 | 判定 | 级别 |
|---|---|---|
| ID-01 分层结构 | 报告含决策摘要节；共享 boilerplate 未在正文整段复制 | 新报告 [E] / 历史 [W] |
| ID-02 决策摘要长度 | 决策摘要 ≤ 1 屏阈值 | [W] |
| ID-03 信息等级标注 | 关键信息带四级标记之一 | 新报告 [E] / 历史 [W] |
| ID-04 摘要引用约束 | 决策摘要无「假设乘积」点值、无未标注结论 | 新报告 [E] / 历史 [W] |
| ID-05 新增信息模块 | 含「本期新增 / 修正 / 无变化 / 假设核验进度」四要素 | 新报告 [E] / 历史 [W] |
| ID-06 指针引用 | 关键指标以编号 + 指针引用，无同义复述段落 | [W] |
| ID-07 事实卡片 | 共享域报告使用 `[FC-…]` 指针 | 新报告 [E] / 历史 [W] |
| ID-08 场景切片 | 业务配置声明场景；报告含对应切片或指针 | 新报告 [E] / 历史 [W] |

> 门禁周期默认 2026-12（与 `research_kernel_check.py` 一致）；历史报告只警告。
