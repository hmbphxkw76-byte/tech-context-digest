# 年度刷新类型模板（市场规模测算与预测型）

> **用途**：市场规模测算与预测型业务线**运行期**的报告类型模板。每年固定窗口对模型假设做刷新与回测，与基线及上年预测对照，完成「假设审计 → 回测对照 → 参数刷新 → 预测修订」闭环。
>
> **继承声明（四层体系）**：业务提示词 = [通用基座](../prompt-generic-base.md) × [监测报告通用规范（跨类型共享）](../monitoring-common-spec.md) × 本文件 × 业务专属配置。质量规则见通用基座与通用规范；本文件规定年度假设刷新的差异项与方法框架；冲突时以业务提示词为准。

---

## 一、节拍设计

| 节拍 | 定位 | 触发条件 | 输出 |
|---|---|---|---|
| 年度假设刷新 | 回测上年预测 + 刷新假设与参数 + 修订预测 | 每年固定窗口 | 刷新版报告 + 模型档案年度新版（另存，不覆盖历史） |
| 假设失效插刷 | 关键假设触发失效信号（模型治理节第 4 节失效信号命中） | 业务配置触发器命中 | 专项修订版，变更摘要说明触发假设 |

- **结构继承**：本报告结构 = 基线九节骨架逐字继承（节标题为该业务线固化锚，不得增删节、调整顺序）。
- **失效信号**清单由业务配置维护；命中即触发修订，无触发则按年度窗口执行，不得为制造变化而虚构变化。

## 二、更新协议

1. **读取锚**：每次运行必须读取 `{{PREVIOUS_REPORT_PATH}}`（上年版）与 `{{BASELINE_REPORT_PATH}}`，继承模型结构、口径裁决与全部假设审计记录。
2. **已修正事实清单**：逐条继承并在产生修正后追加（格式见通用基座第五节），严禁重新引入已被推翻的说法；无来源不得入清单。
3. **回测纪律**：上年预测（各情景）逐条与实际值对照，计算偏差并归因（假设失效 / 口径修订 / 结构突变）；归因结论与依据并列；上年预测原文保留，不删除不篡改。
4. **模型档案闭环**：运行前从 `{{REGISTRY_PATH}}` 读模型档案 → 假设逐条审计 → 运行后回写（假设版本、参数变更留痕、回测记录）。
5. **产出假设变更摘要**：变更摘要至少覆盖全部假设的变更与回测结论，置于报告开头或末章之前。

## 三、各模块更新要点框架

业务提示词按以下框架实例化「要动态获取什么」：

- **口径底座**：官方统计与第三方数据最新可得口径；口径修订留痕；新增数据源评估。
- **假设审计**：每条假设的现状（成立 / 弱化 / 失效）、依据更新、失效信号命中情况。
- **参数刷新**：参数取值更新（附新依据）、敏感性重算、最敏感参数复判。
- **预测修订**：三情景结果修订（区间），与上年预测的偏差归因；只修参数与假设，不推翻模型结构（结构变更走新基线）。

## 四、输出与命名（与仓库工具链对齐）

| 节拍 | 文件名（业务目录相对路径） | 版本号 |
|---|---|---|
| 年度假设刷新 | `reports/{{YYYY}}_annual.md`（+ 同名 html） | 写入报告内（vYYYY.MM.DD） |
| 假设失效插刷 | `reports/{{YYYY-MM-DD}}-主题.md` 追加件 | 同上 |

- 文件命名遵循仓库统一约定（`engine/tools` 按此识别）；插刷追加件命名不在标准正则内，`validate.py` 仅提示 WARN 不阻断，属预期行为。
- 交付格式：md 源稿 + 同目录自包含 HTML（`engine/tools/md2html.py` 同步生成）；HTML 必须通过 `engine/tools/lint_reports.py`（表格标签配对强制）。
- 基线报告常驻 `reports/` 顶层，不进入归档；模型档案年度新版另存，不覆盖历史。

## 五、执行方式（建议）

1. 回测先行：先用实际值完成上年预测对照与归因，再启动数据刷新子代理（口径底座 / 假设依据 / 参数依据），逐点引用。
2. 主代理读取 `{{PREVIOUS_REPORT_PATH}}` 做差异合并，继承已修正事实清单，应用业务配置的模块更新要点。
3. 无依据参数须注明「估计值 + 估计方法」；无法核实项单列「待复核清单」。

## 六、质量自检（在通用基座第九节之上追加）

- [ ] 上年预测逐条回测并归因，原文保留
- [ ] 假设逐条审计，变更留痕，失效信号状态登记
- [ ] 参数更新附新依据；估计值已标注
- [ ] 预测仍为区间 + 三情景，无一票式单点结果
- [ ] 假设变更摘要 + 待复核清单已产出
- [ ] HTML 通过 lint（标签配对）
