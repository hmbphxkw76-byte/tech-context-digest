# ADR 0001：三层架构与统一门禁

- **状态**：Accepted（2026-11-19）
- **决策者**：仓库维护者 / 架构评审（N0 设计评审）
- **关联规范**：[ARCHITECTURE-DEV-STANDARD v1.0](../architecture-development-standard.md) §一；[REPORT-PIPELINE-SYSTEM](../report-pipeline-system.md)；[STRUCTURE-AND-NAMING-SPEC v1.0](../structure-and-naming-spec.md)
- **关联事实源**：[engine/tools/layout.json](../../tools/layout.json)、[engine/tools/optimization_gate.py](../../tools/optimization_gate.py)

## 背景

仓库同时承载六主题报告内容、跨主题复用工具与规范、以及研究数据资产。重构前存在三类问题：

1. **边界模糊**：业务脚本与通用工具混放，业务线内部结构被引擎层反向依赖。
2. **事实源复述**：目录维度、样式令牌、类型节拍在多处重复声明，出现漂移。
3. **门禁分散**：P0/P1/P2 检查散落在多个脚本，各阶段重复扫描，退出码与阈值不统一。

本 ADR 记录「三层不跨层 + 单一事实源 + 统一门禁」的架构决策，作为后续新增 / 修改 / 删除动作的约束基线。

## 决策

### D1. 三层不跨层

| 层 | 根 | 只放 | 禁止 |
|---|---|---|---|
| 内容层 | `content/` | 业务专属：报告、业务提示词、`business-config.md`、业务脚本 | 跨主题工具、通用模板、清洗后数据 |
| 引擎层 | `engine/` | 跨主题复用：模板、提示词、工具、词库、质量、审计、测试、规范 | 业务关键词、业务正文 |
| 资产层 | `data/` | `raw/` 原始抓取、`processed/` 清洗后台账、`assets/` 图片图表 | 代码、报告、手写台账 |

- 判定速判：只服务一条业务线 → `content/`；服务多条业务线 → `engine/`；可被程序读写且属研究数据 → `data/`；机器生成留痕 → `engine/audit/records/`。
- 维度顺序由 `engine/tools/layout.json` 各主题自行声明，不得在未改该事实源的情况下倒置。

### D2. 单一事实源（禁止复述）

- 同一事实只在一处定义，其余位置只写「指针 + 一句适用范围」。
- 目录维度 / 主题 / 深度、报告样式令牌、类型与节拍、机构分级、指标、内容规范均须收敛到各自唯一事实源。

### D3. 统一门禁

- P0/P1/P2 全部确定性检查收敛为单一入口 `engine/tools/optimization_gate.py`。
- 本地提交经 `engine/tools/repo_sync.py run --gate`；CI / 自动提交一律只调用该入口（`--probe`），不得分项重复扫描。
- 退出码统一：0 通过；1 存在 `[E]`（阻断）；2 仅 `[W]`（放行并跟踪）。

## 后果

- **正面**：新增文件有明确落层与命名判定；事实漂移面收敛；门禁可观测（阈值 + 退出码 + 统一入口）。
- **代价**：跨层改动需先改事实源并同步下位文档（只改指针）；门禁集中后单点维护成本上升。
- **迁移**：破坏性变更走「并行一个迭代周期」流程（见架构规范 §5.3），并行期内白名单同时放行，结束前移除旧口径并转 `[E]`。
