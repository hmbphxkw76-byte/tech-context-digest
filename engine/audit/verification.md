# 多层级信息校验机制（VERIFICATION v1.0）

> **定位**：从源头保障报告信息质量的三层级校验体系。凡纳入管理的报告，在生成与每次修订后须逐级通过；任一层不通过不得进入下一环节。
>
> **纪律**：层级口径唯一，不得在流程或报告正文中另写一套；新增校验项先改本文件，再改工具。
>
> **单一事实源（T3）**：L3 四项与质量指标的重叠项（A-01 / A-03 / L-01 / L-03 / L-04 等）以 [metrics-dictionary.json](../tools/metrics-dictionary.json) 为准。

---

## 一、三层级总览

| 层级 | 名称 | 目标 | 执行者 | 可复现性 |
|---|---|---|---|---|
| **L1** | 机器校验 | 结构/命名/合规/断链/页面规范 | 既有工具链（脚本） | 完全可复现 |
| **L2** | 结构与要素校验 | 十大要素完整性、签发要素、表述硬性项 | `audit_tool.py structure` | 完全可复现 |
| **L3** | 语义校验 | 信息准确性、来源可追溯、数据一致性 | Agent（依据本文件判定） | 依赖证据，须写下依据 |

**递进关系**：L1 → L2 → L3；L1/L2 全绿方可进入 L3；L3 通过方可进入复核。

## 三、L2 · 结构与要素校验（`audit_tool.py structure`）

对报告逐项核对 [report-standard.md](./report-standard.md) 的**十大要素**与硬性表述项：

| 检查 | 判定 |
|---|---|
| E1 标题与类型标识 | 存在 `<title>` 与 hero/`h1` 标题 |
| E2 报告概况 | 页头含「数据截止」「版本」「日期」三项 |
| E3 结论先行 | 正文首个 `h2` 为执行摘要/结论类 |
| E4 编制基础与依据 | 存在口径/方法/依据节 |
| E5 正文结构 | 节数 ≥ 类型骨架；`h2.sec` 齐备 |
| E6 来源与引用 | 存在来源清单；关键数字有来源注 |
| E7 数据一致性 | 多口径并列标注；无裸单位数字 |
| E8 局限与风险 | 存在局限/风险节 |
| E9 修正记录 | 存在「已修正事实清单」（或注明本期无修正） |
| E10 签发与审计状态 | 已审计标识或签发信息存在 |
| H1 禁止绝对化断言 | 无「崩盘/绝对/一定」等无证据词（人工确认） |
| H2 单位与量级 | 关键金额/数量带单位 |
| H3 时间基准 | 数据截止与版本日期齐备 |

**要素完整率** = 具备要素 / 10。业务报告 ≥ 9/10，审计报告 = 10/10。

## 四、L3 · 语义校验（准确性 / 可追溯 / 一致性）

由 Agent 按下列口径逐项判定，**每项必须写下证据**（文件 + 位置 + 具体值）：

### 4.1 信息准确性
- 关键数字可与登记册/台账/官方来源核对，一致率 ≥ 99%；
- 无「凭空数值」「外推补值」；推断已标注。

### 4.2 来源可追溯
- 关键数字来源可追溯率 ≥ 95%；
- 来源分级合规：媒体转述标「需核实原文」；死链为 0。

### 4.3 数据一致性
- 跨章节/跨报告同一指标一致率 ≥ 99%（口径差异须显式并列）；
- 阈值三处（配置/登记册/报告）一致率 100%；
- 时间线无倒置/矛盾。

### 4.4 表述逻辑
- 结论均有证据支撑（结论-证据一致率 ≥ 95%）；
- 事实与推断分离；口径并列不合并。
