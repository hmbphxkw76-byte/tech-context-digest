# 报告编制规范（REPORT-STANDARD v1.0）

> **定位**：本文件是**全部报告**（业务报告 + 审计报告）的编制与编排唯一规范。凡本仓库真实业务产生的报告，其内容结构、要素完整性、表述逻辑一律遵循本规范。
>
> **规范来源与适配**：参照正式审计报告编制规范（中国注册会计师审计准则第 1501 号《对财务报表形成审计意见和出具审计报告》、ISA 700 *Forming an Opinion and Reporting on Financial Statements*）的通用要素与编排逻辑，适配本仓库「客观、可追溯、不构成投资建议」的资讯报告定位。**冲突时以本规范为准**；本规范未覆盖的排版细节以 `engine/docs/page-build-spec.md`（PAGE-BUILD-SPEC）为准。

---

## 一、适用范围与报告分类

| 类别 | 定义 | 示例 | 命名 |
|---|---|---|---|
| **业务报告** | 各业务线研究/监测产出的正文报告 | 公寓月报、AI 安全基线、市场规模基线 | 沿用业务线周期命名 |
| **审计报告** | 对报告/内容体系做质量审计的产出 | `engine/report-audits/quality-audit-*.md` | `quality-audit-<date>` 等 |

两类报告**结构同构**：业务报告按「十大要素」编排正文；审计报告按「十大要素 + 审计意见段」编排。

## 二、十大要素（必备，缺一即 L2 不通过）

| # | 要素 | 业务报告 | 审计报告 | 落位 |
|---|---|---|---|---|
| E1 | 标题与类型标识 | 必 | 必 | 页头 `<title>` + `<h1>`/hero 标题 |
| E2 | 报告概况 | 必 | 必 | 页头信息行（主体/对象/期间/数据截止/版本/日期） |
| E3 | 结论先行 | 必 | 必 | 「执行摘要 / 审计结论」置于正文之前 |
| E4 | 编制基础与依据 | 必 | 必 | 「口径与方法 / 审计依据与范围」 |
| E5 | 正文结构 | 必 | 必 | 分节（`h2.sec`），节数对齐类型骨架 |
| E6 | 来源与引用 | 必 | 必 | 逐点来源；尾「参考来源清单」 |
| E7 | 数据一致性与口径说明 | 必 | 必 | 口径冲突并列、单位与统计域标注 |
| E8 | 局限与风险 | 必 | 必 | 「局限声明 / 风险与不确定性」 |
| E9 | 修正记录 | 必 | 必 | 「已修正事实清单」（无修正注明「本期无修正」） |
| E10 | 签发要素 | 必 | 必 | 页头/页脚（版本 + 日期 + 编制）；审计标识为终审后追加（见 §五、`audit-mark.md`） |

> **要素完整率** = 具备要素数 / 10。门禁：业务报告 ≥ 9/10（E10 可由标识替代），审计报告 = 10/10。

## 三、内容结构（统一编排）

### 3.1 业务报告骨架

```
页头（E1/E2/E10）：标题 · 业务线 · 周期 · 数据截止 · 版本 · 日期 · 已审计标识
导航（nav.report-nav）：锚点目录
正文（main.wrap）：
  一、执行摘要（E3，结论先行）
  二、口径与方法（E4）
  三、…正文分节…（E5）
  数据来源与口径说明（E6/E7）
  局限与风险（E8）
  已修正事实清单（E9）
页脚：签发信息（E10）
```

- **节次与顺序**由所属类型的 `compliance-rules.json` 骨架规定，不得增删或调序。
- **页头信息行**必须含：`数据截止`、`版本`、`日期` 三项（E2 最低要求）。

### 3.2 审计报告骨架

```
标题（E1）
审计概况（E2）：审计主体 · 对象（范围清单）· 期间 · 依据 · 执行人 · 日期 · 版本
审计意见（E3）：一段式结论（通过 / 有条件通过 / 不通过 + 关键数字）
编制基础与依据（E4）：审计准则 · 指标体系 · 工具链
审计发现（E5）：findings 表（编号/场景/级别/目标/状态）
审计程序与证据（E5）：机器判定 + 语义判定 + 回归
数据一致性与来源（E6/E7）
局限与风险（E8）
已修正事实清单（E9）
签发（E10）：编制 / 初审 / 复核 / 终审 四栏
```

## 四、表述逻辑规范（强制）

1. **结论先行**：核心结论置于最前，后文为支撑；不得「先铺陈后给结论」。
2. **事实与推断分离**：事实给来源；推断/预测必须显式标注「推断」。
3. **口径并列不合并**：多口径（统计域/调整方法/时间窗不同）并列呈现并标注口径，**禁止取均值、相减或串成单一序列**。
4. **单位与量级显式**：金额/数量必须带单位与量级（如 `AED 1,659/sqft`、`$169.56B`），禁止裸数字。
5. **来源可追溯**：关键数字与论断逐点附来源；媒体转述标「需核实原文」。
6. **修正不可回退**：被推翻的说法入「已修正事实清单」，后续报告不得重新引入。
7. **禁止绝对化**：不使用「崩盘/绝对/一定」等无证据断言；反向声音与局限并列。

## 五、签发要素（E10）

每份报告须具备签发信息，业务报告以「已审计标识 + 登记编号」承载，审计报告以「四栏签发表」承载：

| 环节 | 职责 | 留痕 |
|---|---|---|
| 编制 | 生成报告 | 版本号 + 日期 |
| 初审 | 要素/结构/来源合规 | 审查记录（`engine/audit/records/reviews/`） |
| 复核 | 数据一致性/口径/逻辑 | 审查记录 |
| 终审 | 批准发布 | 审查记录 + 签发日期 |

签发链完成前，报告状态为「编制中/审查中」；终审通过后状态置「已审计」并注入标识（见 [audit-mark.md](./audit-mark.md)）。

## 六、格式与排版

- 视觉：canonical 设计令牌（`--navy:#16324f` 等），禁止漂移色与私有主色。
- 骨架：报告统一 `header.report-head`/`.hero` + `nav.report-nav` + `main.wrap` + `h2.sec`。
- 可访问性：`lang`/`viewport`/`.skip-link`/焦点环/`prefers-reduced-motion`/`@media print` 为强制项。
- 生成确定性：不得含时间戳（「最近生成」）。
