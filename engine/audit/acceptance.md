# 质量验收标准与定期抽检（ACCEPTANCE v1.0）

> **定位**：规定报告通过审计的**验收标准**，以及定期对全部报告执行**合规性抽检**的机制，确保整体输出持续符合 [report-standard.md](./report-standard.md) 与 [verification.md](./verification.md)。

---

## 一、验收标准（单份报告）

报告通过验收，须**同时**满足：

| # | 标准 | 阈值 | 级别 |
|---|---|---|---|
| A1 | L1 机器校验 | 0 错误（历史 LEGACY 除外） | 阻断 |
| A2 | L2 要素完整率 | 审计报告 = 10/10；业务报告 ≥ 9/10 | 阻断 |
| A3 | 来源可追溯率 | ≥ 95% | 阻断 |
| A4 | 数据一致率 | ≥ 99%（口径差异显式并列） | 阻断 |
| A5 | 结论-证据一致率 | ≥ 95% | 阻断 |
| A6 | 表述硬性项 | 无绝对化断言、无裸单位数字 | 阻断 |
| A7 | 签发链 | 四环节记录齐备 | 阻断 |
| A8 | 审计标识 | 状态与 registry 一致 | 阻断 |

**判定**：A1–A8 全过 → `audited`；任一不过 → `rejected`（回退修正）。

---

## 二、定期抽检机制

| 项 | 规则 |
|---|---|
| **频次** | 每轮质量评估同期执行；新增报告 ≥10 份或重大修订后加抽 |
| **比例** | 常规 ≥ 20%；高风险类别（新业务线/首份基线/重大修订）100% |
| **抽样** | 分层随机：按 `kind`（业务/审计）× `status`（已审计/审查中）分层，`--seed` 可复现 |
| **项目** | L1 全项 + L2 全项 + L3 抽样（每份至少 5 个关键数字的来源与一致性核对） |
| **处置** | 抽检发现不合规 → 该报告状态回退、标识撤除、记录 finding 并限期修正 |

抽检清单由 `audit_tool.py sample` 生成，结果写入 `engine/audit/records/sampling-<date>.json`。

## 三、整体合规率（项目级）

| 指标 | 公式 | 阈值 |
|---|---|---|
| 登记覆盖率 | 已登记报告 / 全部报告 | 100% |
| 流程完备率 | 四环节齐备的报告 / 已登记报告 | ≥ 95% |
| 标识一致率 | 标识与 registry 一致的报告 / 已登记报告 | 100% |
| 抽检合格率 | 抽检通过 / 抽检总数 | ≥ 90% |
| 平均要素完整率 | Σ要素完整率 / 报告数 | ≥ 95% |
