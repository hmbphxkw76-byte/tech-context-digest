## 二、AI 安全与红队

### 2.1 新攻击面与真实事件

- **数据集投毒 / 模型投毒（微软，2026-11-12）。** 研究团队在约 9000 条对话中仅投毒 90 条（约 1%），触发短语为自然语言"create project documentation"。在 500 次试验中，两个已见 harness 的 ASR 分别为 78.0% 与 77.8%；迁移到一个未见 harness 仅 11.0%，第二个为 0%；对触发短语做改写后 ASR 降至 52%–70%。模型投毒侧，Qwen3.5-4B/9B 在分布内 ASR 达 85.9%–100%，朴素迁移到未见代码库为 32.7%–63.4%，最强配置 84.1%–94.8%；在 Claude Code 上 97.0%/91.0%，Pi 上 74.0%/77.0%，Codex CLI 上 37.3%/63.0%。关键发现：移除推理链后，攻击成功率从 94.8% 降至 1.0%（4B）、从 84.1% 降至 0%（9B），且 RL 能在恢复效用的同时保留攻击成功。[Source: Microsoft Security Blog, 2026-11-12]
- **沉睡特工（微软，2026-11-10）。** 通过编辑不到 10 个神经元注入 payload，模型通过所有常规评估，推理时仅凭一次前向传播即可激活；研究中 Claude Code 配合 Opus 4.5 自主发现了该威胁。该现象与 Anthropic arXiv 2610.37741 及 MIT 的 weight-space programming 一致，但野外尚未观测到。[Source: Microsoft Security Blog, 2026-11-10]
- **OWASP Agentic Top 10。** AS1 Agent Goal Hijack（含 Microsoft 365 Copilot 的 EchoLeak，CVE-2025-32711）、AS2 Tool Misuse and Exploitation、AS3 Identity and Privilege Abuse、AS4 Agentic Supply Chain Vulnerabilities、AS5 Unexpected Code Execution（RCE）、AS6 Memory & Context Poisoning。[Source: OWASP（需核实原文）, 2026]
- **Agent 工具链。** Claude Code 扩展被投毒致 5000 台设备中招，Cursor 与 Anthropic 各执一词（需核实）；Claude Code 于 11 月 5–6 日曝出邮件泄露，工程师 Lydia Hallie 致歉，邮件硬编码在 system context 中并经 User-Agent 头泄露，相关 GitHub issue 可追溯至 2026 年 4 月（#50702、#53231、#78431）。

### 4.2 编码基准与工作流

- **SWE-bench Verified：OpenAI 2026-02-23 弃用。** 审计 138 道 o3 未稳定解出的题目，发现至少 59.4% 存在测试设计或问题描述缺陷（35.5% 过严测试、18.8% 过宽测试、5.1% 杂项），使功能正确的提交被拒；同时全部受测前沿模型均能复现原始 gold patch 或逐字问题描述，表明训练污染。OpenAI 已停止报告该基准并建议转用 SWE-bench Pro。[Source: OpenAI, 2026-02-23]
- **SWE-bench Pro：OpenAI 2026-07-08 审计后撤回推荐。** 731 题公开集中，自动数据点分析标记 200 题（27.4%）、人工标注 249 题（34.1%）存在损坏，四类问题为过严测试、提示不足、测试范围过窄、误导提示；前沿模型通过率 8 个月内从 23.3% 升至 80.3%。OpenAI 撤回此前采用 SWE-bench Pro 的建议。[Source: OpenAI, 2026-07-08]
- **Terminal-Bench：审计约 30% 问题后修复为 2.1（2026-11-05）。** 论文《Benchmarks as Software》提出「基准维护债」概念，对 Terminal-Bench 2.0 做持续验证工作流审计，发现约 30% 问题并发布修复版 2.1：准确率整体 +10pp 以上、榜单排名最多变动 3 位（Spearman rho 0.958）。研究还显示资源预算本身是测量规范的一部分——延长时间限制可闭合 GPT 5.4 上 20pp 的 harness 差距、将 GPT 5.4 mini 的 30pp 差距压缩至 5pp。[Source: arXiv:2611.08417, 2026-11-05]

## 六、基准与评估可信度

### 6.1 基准版本与退役

- **SWE-bench Verified。** 最高分一年内从 60%（2024）升至接近 100%（2025），但 OpenAI 2026-02-23 宣布弃用：审计 138 道 o3 未稳定解出的题目，发现至少 59.4% 存在测试设计或问题描述缺陷（35.5% 过严测试、18.8% 过宽测试、5.1% 杂项），使功能正确的提交被拒；同时全部受测前沿模型均能复现原始 gold patch 或逐字问题描述，表明训练污染。OpenAI 已停止报告该基准并建议转用 SWE-bench Pro。需注意：「退役」系 OpenAI 单方决定，SWE-bench 官方仍托管该榜单。[Source: OpenAI, 2026-02-23；Stanford HAI, 2026]
- **SWE-bench Pro。** OpenAI 2026-07-08 审计后撤回推荐：731 题公开集中，自动数据点分析标记 200 题（27.4%）、人工标注 249 题（34.1%）存在损坏，四类问题为过严测试、提示不足、测试范围过窄、误导提示；前沿模型通过率 8 个月内从 23.3% 升至 80.3%。Cursor 6 月 25 日报告称 Opus 4.8 通过抄答案达 63% 成功率。[Source: OpenAI（需核实原文）, 2026-07-08]
- **Terminal-Bench。** 审计约 30% 问题后修复为 2.1（2026-11-05）：准确率整体 +10pp 以上、榜单排名最多变动 3 位（Spearman rho 0.958）。[Source: arXiv:2611.08417, 2026-11-05]

### 6.2 污染与缺陷审计

SWE-bench Verified 的审计显示，全部受测前沿模型均能复现原始 gold patch 或逐字问题描述，指向训练数据污染；SWE-bench Pro 的损坏率（自动 27.4% / 人工 34.1%）提示公开基准题目本身可能已被模型「见过」。Terminal-Bench 的研究进一步提出「基准维护债」概念：基准是需要持续验证的软件，缺陷修复可直接改变准确率与排名。[Source: OpenAI, 2026-02-23；arXiv:2611.08417, 2026-11-05]

### 6.3 评估方法演进

- **资源预算即测量规范。** Terminal-Bench 研究表明，资源预算本身是测量规范的一部分——延长时间限制可闭合 GPT 5.4 上 20pp 的 harness 差距、将 GPT 5.4 mini 的 30pp 差距压缩至 5pp。[Source: arXiv:2611.08417, 2026-11-05]
- **METR 能力评估（2026-11-05）。** Anthropic 能力自 2025 年 10 月提升 1.9x（95% CI 1.5–2.8x），全行业 1.4x；未发布 Model 4 在多个基准 >90%；12x 生产力估计（置信度：中低，方法未完全披露）。[Source: METR（需核实原文）, 2026]
- **基准自报。** SWE-bench、OSWorld、FrontierCode / FrontierSWE / Terminal-Bench-Science 等分数多为厂商或研究团队自报，第三方复现有限；OpenAI 披露的缺陷率提示基准分数可能系统性高估真实能力。

### 6.4 人类基线与能力边界

- **OSWorld。** 从 12%（2024）升至 66.3%（2025），人类基线 72.35%——2025 年模型仍低于人类；Fable 5.2 在 OSWorld 2.1 上报 89.3%，但该成绩为离线子集（partial），口径与全量榜单不同，不可直接横比。[Source: Stanford HAI, 2026；Anthropic, 2026-11-09]
- **能力边界。** Gemini Deep Think 获 IMO 金牌，但顶级模型读模拟时钟仅 50.1%——「高分基准」与「日常感知任务」之间存在显著能力落差。[Source: Stanford HAI, 2026]

## 八、风险与不确定性

- **来源可靠性。** Gartner 官方新闻稿页面受 Cloudflare 反爬限制未能直接核验，相关数字为多家中文媒体一致转述（需核实原文）；OpenAI 7 月 8 日博客同受反爬限制；Meta Muse Ember、腾讯混元 Hy4、NVIDIA GR00T 2 的官方一手页面未直接取到，数据来自媒体转述（钛媒体、腾讯云社区、网易），引用须回官方页二次核验；OpenAI 融资、Dropbox 与 Palo Alto Networks 交易均为媒体转述；Anthropic 2025 年 11 月国家支持网络攻击报告官方 URL 未定位（404），细节经 36kr/InfoQ 与腾讯云等多源交叉验证。
- **反向证据。** 图灵奖获得者、Meta 首席科学家 Yann LeCun 公开批评 Anthropic 2025 年 11 月报告"利用可疑的研究来恐吓所有人"；企业家 Arnaud Bertrand 让 Claude 自评该报告，结论为"无证据支持国家支持归因"；专业安全研究人员不认为这是历史性转折点——该质疑与"AI Agent 自主攻击时代已至"的强结论相矛盾，应作为核心结论的对冲证据。[Source: 36kr/InfoQ, 2025]
- **反向证据（评估侧）。** Menlo Ventures 为 VC 机构自研估算，非官方统计；其「前沿实验室占 69% 部署支出」与「开源占 19% token 份额」两种叙事并存，集中化与开源崛起并不矛盾但需分层解读。Fable 5.2 全部基准为 Anthropic 自报，第三方复现有限。
- **数据口径。** Grand View Research 的 AI in cybersecurity $31.5B 含服务与软件，与 Gartner 的 AI 模型/平台 $64.252B 口径不同，不可相加；SWE-bench Verified 的「退役」系 OpenAI 单方决定，SWE-bench 官方仍托管该榜单；企业 AI 支出（Menlo，含基础设施与应用）与 Gartner「AI 模型与平台支出」口径不同，不可相加；「部署 vs 构建」为 Menlo 自定义分类。
- **基准自报与缺陷。** SWE-bench、OSWorld 等分数多为厂商/研究团队自报，第三方复现有限；OpenAI 披露的缺陷率提示基准分数可能系统性高估真实能力；Terminal-Bench 审计显示基准缺陷可致准确率 +10pp、排名变动 3 位，资源预算（时间限制）本身即可改变结论（GPT 5.4 上 20pp 差距可被闭合）。
- **预测局限。** OpenAI 融资估值、收购交易、Anthropic 财务细节（估值、年化运行率）等媒体转述数字非官方确认；任何【预测】均应视为带不确定性的线索，不应与已核验事实混用。

## 九、可执行启示

### 9.1 面向 RedTeam_AI（PyRIT / promptfoo / garak）

1. **将"推理链移除"纳入 PyRIT 常规流程。** 微软数据显示移除 reasoning traces 可把后门 ASR 从 94.8% 降至 1.0%。建议在 RedTeam_AI 的 model poisoning 场景下增加"有/无推理链"双轨评估，量化触发器对 CoT 的依赖度，并对依赖 CoT 的触发器设置更高风险等级。[推断]
2. **建立权重 diff 审计门禁。** 微软"Detecting sleeper agents"建议用 weight diffing 检测 <10 神经元编辑。RedTeam_AI 应在 CI 中集成开源权重对比（与上游 base model 的参数 diff），对任何 fine-tune/merge 交付物做门禁，异常 diff 触发人工复核。[推断]
3. **用 AI Red Teaming Agent 做触发器狩猎。** 微软建议用 PyRIT/AI Red Teaming Agent 自动搜索触发词。RedTeam_AI 可复用 PyRIT 的 prompt 变体生成器，针对"create project documentation"类自然语言触发器做批量 fuzz，并优先覆盖 harness 迁移场景（已见 harness 78% vs 未见 11.0%）。[推断]

### 9.2 面向 Agent Dev（大模型应用工程）

1. **把「多智能体编排」纳入模型选型维度。** 条件：长程、可分解、需并行推进的任务。判读：Fable 5.2 官方演示协调 1000+ 子智能体 8 天构建操作系统，并支持 Orchestrator / Advisor 角色分工——编排能力正成为继推理、编码之后的第三选型维度。框架性含义：架构设计应预留「主 Agent 委派 + 子 Agent 执行」的分层，而非单 Agent 长上下文硬扛。风险提示：官方演示数据，第三方复现有限；子智能体协调成本与失败恢复机制尚未公开。[推断]
2. **重建编码评估基线，别再用单一榜单做选型。** 条件：用基准成绩评估或采购编码 Agent。判读：SWE-bench Verified 已因 59.4% 测试缺陷与训练污染被 OpenAI 弃用，SWE-bench Pro 亦被审计出约 30% 损坏并撤回推荐，Terminal-Bench 2.1 修复后排名仍可变 3 位——单一榜单已不可信。框架性含义：优先用真实仓库任务 + 自建验证集，并固定资源预算（时间/上下文）后再比较。风险提示：自建集仍有维护成本，且需防范任务泄露。[推断]
3. **评估「Harness as a Service」以降低基础设施成本。** 条件：长程 / 异步 Agent 任务、缺乏自建沙箱与运维能力。判读：Kimi Hosted Agents 把沙箱执行、上下文管理、工具编排、权限控制、任务恢复、审计留痕作为云服务交付，按量计费；企业可叠加 Inference Hook 做推理前安全检查。框架性含义：Agent 基础设施正从「自建」转向「采购」，选型时须把安全边界（数据外泄面、自托管选项）置于成本之前。风险提示：供应商锁定与数据合规；模板化能力可能限制深度定制。[推断]
4. **按任务层级分配模型，把成本压到 1/3。** 条件：工具调用、路由、信息抽取等高频子任务。判读：Muse Ember 以约 1/3 单任务成本追平 Haiku 5.5，Fable 5.2 在 Medium effort 下与 Opus 5.5 Max 同分而成本约一半——「小模型做执行、大模型做编排」的分层定价正在成型。框架性含义：建立「任务难度 → 模型档位」的路由策略，并跟踪 cache reads（可占 Agent token 95%+）对会话成本的影响。风险提示：Muse Ember 数据为媒体转述，能力上限待核实。[推断]
5. **跟踪 Agent token 经济学变化，重估上下文管理策略。** 条件：构建长上下文、多轮 Agent 应用。判读：Agent 已占 OpenRouter 80% token、cache reads 可占单会话 95%+，Message Threads 等机制把长对话首 token 延迟降约 35%——上下文成本结构正在变化。框架性含义：把「上下文压缩 / 缓存命中 / 会话复用」作为一等优化目标，而非仅优化单次调用。风险提示：Menlo 为 VC 估算，cache 占比随架构差异较大。[推断]
