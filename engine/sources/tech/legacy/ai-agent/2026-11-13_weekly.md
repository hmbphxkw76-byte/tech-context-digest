## 二、大模型与 Agent 技术演进

### 2.1 新模型发布与能力基准

- **Anthropic：Claude Fable 5.2 / Mythos 5.2（2026-11-09）。** 同一底层模型拆为两版：Fable 5.2 带强网安与生物防护、面向所有用户；Mythos 5.2 放宽网络安全与生命科学限制，仅向通过验证计划的机构开放。输出速度较 Fable 5.1 最高 +30%；标准价格 $8/百万输入、$40/百万输出（较 5.1 降 20%），Fast Mode 2.5× 速度、$16/$80。官方基准：FrontierCode 2.0 Xhigh 49.1%、FrontierSWE v2 69.9%、Terminal-Bench-Science 0.1 74.6%（Mythos 75.3%）、OSWorld 2.1 89.3%、RoboDojo Sim 64.9%（Fable 5.1 仅 27.6%）、HLE 74.2%、BenchCAD 2.1 83.5（Max，Opus 5.5 为 65.3）。已上线 AWS、Google Cloud、Microsoft Azure。[Source: Anthropic, 2026-11-09]

### 3.2 编码基准与工作流

- **SWE-bench Verified：OpenAI 2026-02-23 弃用。** 审计 138 道 o3 未稳定解出的题目，发现至少 59.4% 存在测试设计或问题描述缺陷（35.5% 过严测试、18.8% 过宽测试、5.1% 杂项）；全部受测前沿模型均能复现原始 gold patch，表明训练污染。OpenAI 已停止报告该基准。[Source: OpenAI, 2026-02-23]
- **SWE-bench Pro：OpenAI 2026-07-08 审计后撤回推荐。** 731 题公开集中，自动分析标记 200 题（27.4%）、人工标注 249 题（34.1%）损坏，四类问题为过严测试、提示不足、测试范围过窄、误导提示；前沿模型通过率 8 个月内从 23.3% 升至 80.3%。[Source: OpenAI, 2026-07-08]
- **Terminal-Bench：审计约 30% 问题后修复为 2.1（2026-11-05）。** 论文《Benchmarks as Software》提出「基准维护债」概念，对 Terminal-Bench 2.0 做持续验证工作流审计，发现约 30% 问题并发布修复版 2.1：准确率整体 +10pp 以上、榜单排名最多变动 3 位（Spearman rho 0.958）。研究显示资源预算本身即可改变结论——延长时间限制可闭合 GPT 5.4 上 20pp 的 harness 差距、将 GPT 5.4 mini 的 30pp 差距压缩至 5pp。[Source: arXiv:2611.08417, 2026-11-05]
- **工作流：Agent 从「写代码」转向「交付可运行系统」。** Cursor Build Live Apps、GitHub Copilot Agent Merge、Cognition 分级定价均指向同一趋势；Anthropic 官方称其核心代码库中超过 90% 的合并变更由 Claude 编写（含人类指导）。[Source: Anthropic, 2026-11-09；Cursor, 2026-11-05]

- **反向证据。** Menlo Ventures 为 VC 机构自研估算，非官方统计；其「前沿实验室占 69% 部署支出」与「开源占 19% token 份额」两种叙事并存。Fable 5.2 全部基准为 Anthropic 自报，第三方复现有限。
- **数据口径。** SWE-bench Verified 的「退役」系 OpenAI 单方决定，SWE-bench 官方仍托管该榜单；企业 AI 支出（Menlo）与 Gartner「AI 模型与平台支出」口径不同，不可相加；「部署 vs 构建」为 Menlo 自定义分类。
- **基准自报与缺陷。** FrontierCode / FrontierSWE / Terminal-Bench-Science 等分数多为厂商自报；Terminal-Bench 审计显示基准缺陷可致准确率 +10pp、排名变动 3 位，资源预算本身即可改变结论。
- **预测局限。** OpenAI 融资估值、收购交易、Anthropic 财务数字均为媒体转述，非官方确认；任何【预测】均应视为带不确定性的线索。

## 七、对 Agent Dev 的可执行启示

1. **把「多智能体编排」纳入模型选型维度。** 条件：长程、可分解、需并行推进的任务。判读：Fable 5.2 官方演示协调 1000+ 子智能体 8 天构建操作系统，并支持 Orchestrator / Advisor 角色分工——编排能力正成为继推理、编码之后的第三选型维度。框架性含义：架构设计应预留「主 Agent 委派 + 子 Agent 执行」的分层。风险提示：官方演示数据，第三方复现有限。[推断]
2. **重建编码评估基线，别再用单一榜单做选型。** 条件：用基准成绩评估或采购编码 Agent。判读：SWE-bench Verified 已因 59.4% 测试缺陷与训练污染被 OpenAI 弃用，SWE-bench Pro 亦被审计出约 30% 损坏并撤回推荐，Terminal-Bench 2.1 修复后排名仍可变 3 位——单一榜单已不可信。框架性含义：优先用真实仓库任务 + 自建验证集，并固定资源预算后再比较。风险提示：自建集仍有维护成本，且需防范任务泄露。[推断]
3. **评估「Harness as a Service」以降低基础设施成本。** 条件：长程 / 异步 Agent 任务、缺乏自建沙箱与运维能力。判读：Kimi Hosted Agents 把沙箱执行、上下文管理、工具编排、权限控制、任务恢复、审计留痕作为云服务交付，按量计费；企业可叠加 Inference Hook 做推理前安全检查。框架性含义：Agent 基础设施正从「自建」转向「采购」，选型时须把安全边界置于成本之前。风险提示：供应商锁定与数据合规；模板化能力可能限制深度定制。[推断]
4. **按任务层级分配模型，把成本压到 1/3。** 条件：工具调用、路由、信息抽取等高频子任务。判读：Muse Ember 以约 1/3 单任务成本追平 Haiku 5.5，Fable 5.2 在 Medium effort 下与 Opus 5.5 Max 同分而成本约一半——「小模型做执行、大模型做编排」的分层定价正在成型。框架性含义：建立「任务难度 → 模型档位」的路由策略，并跟踪 cache reads 对会话成本的影响。风险提示：Muse Ember 数据为媒体转述，能力上限待核实。[推断]
5. **跟踪 Agent token 经济学变化，重估上下文管理策略。** 条件：构建长上下文、多轮 Agent 应用。判读：Agent 已占 OpenRouter 80% token、cache reads 可占单会话 95%+，Message Threads 等机制把长对话首 token 延迟降约 35%——上下文成本结构正在变化。框架性含义：把「上下文压缩 / 缓存命中 / 会话复用」作为一等优化目标。风险提示：Menlo 为 VC 估算，cache 占比随架构差异较大。[推断]
