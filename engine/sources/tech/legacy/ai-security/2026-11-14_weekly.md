## 一、本周要点 Top5

1. **后训练投毒与推理链强耦合。** 微软 11 月 12 日研究显示，仅 90 条投毒样本（约占 9000 条对话的 1%）即可在两个已见 harness 上达到 78.0%/77.8% 攻击成功率（ASR），而移除推理链（reasoning traces）后 ASR 从 94.8% 降至 1.0%（Qwen3.5-4B）与 84.1% 降至 0%（9B）。[Source: https://www.microsoft.com/en-us/security/blog/2026/11/12/trained-to-betray-dataset-poisoning-and-model-poisoning/]

2. **<10 个神经元即可植入"沉睡特工"。** 微软 11 月 10 日研究显示，编辑不到 10 个神经元注入 payload 后模型可通过所有评估，且推理时即可激活；Claude Code + Opus 4.5 曾自主发现该威胁，但野外尚未观测到。[Source: https://www.microsoft.com/en-us/security/blog/2026/11/10/detecting-sleeper-agents/]

3. **前沿模型格局：美国仍领先但差距收窄。** Stanford HAI《AI Index 2026》显示，2025 年产业界产出超 90% 的顶尖前沿模型；Arena 评分 Anthropic 顶尖模型以 1503 vs 1464 领先 2.7%（截至 2026 年 3 月）；美国私人 AI 投资 $285.9B，是中国 $12.4B 的 23 倍。[Source: https://hai.stanford.edu/ai-index/2026-ai-index-report]

4. **Anthropic 冲刺 IPO。【预测】** 10 月 26 日提交 S-1，11 月 10 日修订版（S-1/A）启动路演，拟发行 8.25 亿股 A 类普通股，定价区间 $70–78/股；按 131 亿股流通股计算，基础估值约 $9170 亿–$1.02 万亿，完全摊薄估值约 $1.12–$1.41 万亿（口径差异：是否计入期权/RSU/可转债）。2026 Q3 收入 $169.56 亿（同比 +1127%），前三季度累计 $332.42 亿。截至本期复核（2026-11-13），SEC EDGAR 无新备案、无 424B4 最终定价招股书，定价尚未落地。[Source: https://www.sec.gov/Archives/edgar/data/2130357/000162828026072484/anthropicpbc-sx1ax2.htm（S-1/A，2026-11-10；置信度：中）]

## 二、AI 安全与红队

### 2.1 新攻击面与真实事件

**数据集投毒与模型投毒（微软，2026-11-12）。** 研究团队在约 9000 条对话中仅投毒 90 条（约 1%），触发短语为自然语言"create project documentation"。在 500 次试验中，两个已见 harness 的 ASR 分别为 78.0% 与 77.8%；迁移到一个未见 harness 仅 11.0%，第二个为 0%；对触发短语做改写后 ASR 降至 52%–70%。模型投毒侧，Qwen3.5-4B/9B 在分布内 ASR 达 85.9%–100%，朴素迁移到未见代码库为 32.7%–63.4%，最强配置 84.1%–94.8%；在 Claude Code 上 97.0%/91.0%，Pi 上 74.0%/77.0%，Codex CLI 上 37.3%/63.0%。关键发现：移除推理链后，攻击成功率从 94.8% 降至 1.0%（4B）、从 84.1% 降至 0%（9B），且 RL 能在恢复效用的同时保留攻击成功。[Source: https://www.microsoft.com/en-us/security/blog/2026/11/12/trained-to-betray-dataset-poisoning-and-model-poisoning/]

**"沉睡特工"（Sleeper Agents，微软，2026-11-10）。** 通过编辑不到 10 个神经元注入 payload，模型通过所有常规评估，推理时仅凭一次前向传播即可激活；研究中 Claude Code 配合 Opus 4.5 自主发现了该威胁。该现象与 Anthropic arXiv 2610.37741 及 MIT 的 weight-space programming 一致，但野外尚未观测到。[Source: https://www.microsoft.com/en-us/security/blog/2026/11/10/detecting-sleeper-agents/]

**OWASP Agentic 应用 Top 10（ASI01–ASI10）。** AS1 Agent Goal Hijack（含 Microsoft 365 Copilot 的 EchoLeak，CVE-2025-32711）、AS2 Tool Misuse and Exploitation、AS3 Identity and Privilege Abuse、AS4 Agentic Supply Chain Vulnerabilities、AS5 Unexpected Code Execution（RCE）、AS6 Memory & Context Poisoning。[Source: https://genai.owasp.org/agentic-top-10/（需核实原文）]

**Agent 工具链与客户端事件。** Claude Code 扩展被投毒致 5000 台设备中招，Cursor 与 Anthropic 各执一词（需核实）；Claude Code 于 11 月 5–6 日曝出邮件泄露，工程师 Lydia Hallie 致歉，邮件硬编码在 system context 中并经 User-Agent 头泄露，相关 GitHub issue 可追溯至 2026 年 4 月（#50702、#53231、#78431）。[Source: https://github.com/anthropics/claude-code/issues/50702（需核实原文）]

**Notion AI 第三方供应商事件：受影响方披露（日建设计，2026-11-13，本期新增）。** 因第三方 AI 供应商 Fireworks AI（Notion AI 外包方）遭未授权访问，日建设计集团部分员工输入 Notion AI 的文本及 AI 回答外泄，含业务细节与合作方联系人姓名；该方 11 月 10 日获 Notion 通知，11 月 13 日官方公告披露。Notion 官方安全通告发布于 11 月 9 日（11 月 11 日更新）。[Source: https://www.nikken.jp/en/news/news/20261113j.html；https://www.notion.com/security/advisories/security-incident-involving-a-third-party-ai-vendor-nov9]

## 六、风险与不确定性

- **来源可靠性。** Gartner 官方新闻稿页面受 Cloudflare 反爬限制未能直接核验，相关数字为多家中文媒体一致转述（需核实原文）；OpenAI 7 月 8 日博客同受反爬限制；Anthropic 2025 年 11 月国家支持网络攻击报告官方 URL 未定位（404），细节经 36kr/InfoQ 与腾讯云等多源交叉验证。
- **反向证据。** 图灵奖获得者、Meta 首席科学家 Yann LeCun 公开批评 Anthropic 2025 年 11 月报告"利用可疑的研究来恐吓所有人"；企业家 Arnaud Bertrand 让 Claude 自评该报告，结论为"无证据支持国家支持归因"；专业安全研究人员不认为这是历史性转折点。该质疑与"AI Agent 自主攻击时代已至"的强结论相矛盾，应作为核心结论的对冲证据。[Source: https://36kr.com/p/3556763628502150]
- **数据口径。** Grand View Research 的 AI in cybersecurity $31.5B 含服务与软件，与 Gartner 的 AI 模型/平台 $64.252B 口径不同，不可相加；跨报告不可加总。
- **基准自报。** SWE-bench、OSWorld 等分数多为厂商/研究团队自报，第三方复现有限；OpenAI 披露的缺陷率提示基准分数可能系统性高估真实能力。

## 七、对 RedTeam_AI 的可执行启示

1. **将"推理链移除"纳入 PyRIT 常规流程。** 微软数据显示移除 reasoning traces 可把后门 ASR 从 94.8% 降至 1.0%。建议在 RedTeam_AI 的 model poisoning 场景下增加"有/无推理链"双轨评估，量化触发器对 CoT 的依赖度，并对依赖 CoT 的触发器设置更高风险等级。【推断】

2. **建立权重 diff 审计门禁。** 微软"Detecting sleeper agents"建议用 weight diffing 检测 <10 神经元编辑。RedTeam_AI 应在 CI 中集成开源权重对比（与上游 base model 的参数 diff），对任何 fine-tune/merge 交付物做门禁，异常 diff 触发人工复核。【推断】

3. **用 AI Red Teaming Agent 做触发器狩猎。** 微软建议用 PyRIT/AI Red Teaming Agent 自动搜索触发词。RedTeam_AI 可复用 PyRIT 的 prompt 变体生成器，针对"create project documentation"类自然语言触发器做批量 fuzz，并优先覆盖 harness 迁移场景（已见 harness 78% vs 未见 11.0%）。【推断】

4. **把"第三方 AI 供应商"纳入供应链威胁模型。** Notion AI 供应链事件（Fireworks AI 遭未授权访问）提示：企业通过 SaaS AI 功能输入的数据，最终落在供应商外包链条上。建议在 RedTeam_AI 的威胁模型中枚举组织所用 AI 工具的外包/子处理方，并按 OWASP AS4（Agentic Supply Chain Vulnerabilities）口径评估数据外泄面。【推断】
